# 浏览器标签页与批量密码回归

## 已核实的行为差异

原版 `src/protocol-login.mjs` 已自动执行登录协议、密码提交、邮箱验证码和 OAuth；原版安全验证相关代码依赖 Node/jsdom，传输依赖 Python curl_cffi。Go 迁移按约定改用真实 Chromium 加载浏览器 SDK，并在需要会话绑定后保留 Chromium 网络栈。因此出现验证窗口有明确的架构原因，不能将验证 token 随意移到另一套 TLS 会话来消除窗口。

迁移版本此前对每个 BrowserTransport 请求创建 `background: true` 的普通 target。它仍会显示在标签栏，请求完成再关闭，造成多个临时标题。修复改用 `hidden: true`，并在导航前确认没有关联窗口；人工验证主页面保持可用。版本不支持或忽略该参数时，关闭探测 target 并明确返回 `BROWSER_HIDDEN_TARGET_UNSUPPORTED`。不使用可见标签回退。

请求完成或取消时关闭内部 target。若创建响应丢失而 target ID 未知，或无法确认 target 已关闭，终止该任务拥有的浏览器会话；不影响其他 Chrome 会话。可见窗口测试还检查连续 POST、手动 302、原始重复 Set-Cookie、同会话 Cookie 与取消后的 target 数量。

## 批量资料与密码输入

结构化批量重导入应按原版语义替换密码、TOTP、邮箱 API 和请求体，未提供的对应字段明确清空。此前 Go 遗漏空字段，可能保留上一次导入的旧凭据。只含邮箱的重导入仍复用已有资料；POST 邮箱格式保留公共请求 URL。HTTP/API、Manager 和安全凭据存储之间有组合回归，并检查公开响应不泄漏秘密。

密码输入提示现在分别说明“没有可用密码”和“已提交密码被拒绝”。已导入且被接受的密码仍自动提交；临时服务端错误不会伪装成密码输入请求。原版与 Go 均根据上游最终密码页或邮箱验证页分支；没有证据显示旧版存在“缺少密码时强制切换邮箱验证码”的通用能力。邮箱取码 API 不等同于账号密码。

另一个确定回归是自动密码候选仍留在 Manager 的输入队列中。上游拒绝后，人工输入回调可能再次取出同一旧值；checkpoint 的凭据保存也会重新填入该值。因此在密码验证前、checkpoint 保存后，仅原子移除与当前自动候选相同的队列项。不同的新输入、vault 和密码可用标记均不受清理影响。真实 runner 加本地 Chromium 回归覆盖导入/vault 两种来源，检查拒绝后请求次数保持 1、任务等待、手动新密码仅发送一次、成功输出及安全保存。修复前两种来源均复现重复提交，修复后通过。

当前任务的 `has_password`、`login_mode` 等元数据可能与 runner 加载后的资料不同，不能仅根据这些标记断定本次实际没有密码或密码已被拒绝。没有导出、打印或重新提交真实账号凭据来诊断。历史已取消任务保留其原提示，新提示在新执行过程中生效。

## 验证范围

机器结果保存在 `go-port-browser-batch-regression.json`，原始日志统一归档到本机受控 runtime 的 `archive/browser-batch-regression/`，包含在 `scripts/local-macos.sh clean --yes` 的清理范围内。此前本机部署报告保留，不被新统计覆盖。

实测系统 Chrome 154.0.8037.58，启用 sandbox；该版本记录不是对所有旧浏览器的最低版本保证。测试使用本地合成账号、页面、SDK 和服务，不代表真实上游 Cloudflare、Turnstile、Sentinel 或账号流程全部验收。普通测试和 race 的浏览器条件跳过与显式开启浏览器后的通过分别统计。
