> 历史记录（已被后续清理取代）：本文描述的独立核实、远端恢复、重认证或专项 Cookie 方案不再是当前功能。当前实现以 [设置与重置 2FA](totp-reset.md) 为准；保留本文仅供审计追溯。

本轮接续停用请求 recent-auth 修复，重新检查 HTTP 入口、任务管理器、实际 runner、候选认证、重置状态、凭据交接和前端进度。所有复现使用合成账号、本机 HTTP 服务及临时存储；没有对真实账号发送登录或 2FA 修改请求。

## 第一轮：已复现的问题

1. **人工认证输入被隔离规则误挡。** `Manager.inputLocked` 只允许重置隔离中的 `totp_setup_otp`，因此显式认证恢复的密码、邮箱验证码及停用前原因子验证码即使页面出现输入框，真实 HTTP 提交也返回 409。原前端测试绕过了真实后台准入。
2. **输入放行后的凭据污染风险。** 通用输入函数会把提交的密码直接写入凭据存储，并修改 `HasPassword` / `LoginMode`。候选认证输入必须只供当前活动步骤消费，不能因 HTTP 接收成功就替换原凭据基线。
3. **真实 API 丢失认证运行状态。** `publicJob` 先清除私有 `Input`，后读取其中的 `totpReauthenticate`，导致实际单条、列表及选择接口中的 `totpReauthenticationActive` 恒为 false。修复只在脱敏前提取布尔值，不公开私有输入。
4. **认证后的恢复进度被错误覆盖。** 运行模式贯穿恢复全程，前端却据此一直显示“验证身份中”。现在在真实恢复、登记、激活和保存阶段展示“2FA 恢复中”与当前安全提示；再次进入认证时才展示认证进度。
5. **已认证会话失效后的恢复死路。** 已完成密码及回调的候选，或者已采用的认证会话，之后失效时只能重复读取同一个失效会话；原拒绝回执尚未消费也无法再次认证。该问题需要在明确未发生新安全修改的边界，保存绑定当前认证尝试的拒绝事实，再让用户显式续认证。

## 保持的流程约定

- Cookie 仍由现有成熟 cookiejar 及其持久化快照管理，不按 Cookie 字段名、分片或格式判断登录。
- 停用完整成功回执可靠保存后直接登记新 2FA，不插入额外停用状态 GET。
- 未知修改结果不重放。原操作、请求尝试、回执、待激活密钥和 Cookie 均保留；普通恢复不会自行重新登录。
- 重启只恢复记录与操作入口，等待用户点击继续；不会自动发送验证码或修改账号。
- 人工输入只开放给活动的显式认证恢复，精确匹配等待步骤；原因子 MFA 仅限停用前认证。旧输入、重复提交、混入字段、普通恢复及其他操作仍被拒绝。
- 已验证的新密钥优先完成本地凭据保存和会话交接，不以重新登录代替本地收尾。完成请求的幂等回执继续阻止重复重置。

## 分层验证记录

- Manager 新红测试先复现密码、邮箱和 MFA 输入全部被拒，修复后通过；验证输入可且仅可消费一次、凭据与隔离状态不变、元数据无临时秘密。
- 真实 Console HTTP 覆盖六个正向输入分支、六个负向分支、脱敏后的运行状态和等待输入重启。
- 实际 runner + Console + Manager + Sentinel 工作进程的本机整链测试覆盖自动认证，以及原密码和 MFA 被明确拒绝后手动补输，最终完成同一重置操作和会话交接。

## 第二轮：交叉审查与恢复边界修正

- 对管理器输入、公开 API 脱敏、前端阶段识别和协议续认证分别进行独立交叉审查。输入模式仅由通过准入的显式恢复建立；外部原始输入不能注入模式或改写其他凭据。
- 已采用认证的失效覆盖三个中断窗口：采用后、创建新修改尝试的准备阶段、请求明确未发出时。只有原完整认证拒绝仍可追溯、没有新密钥/激活材料、后续安全修改明确未发送，才接受明确的只读会话拒绝。
- `page` / `session` / `mfa_info` 的明确拒绝可以保存续认证依据。普通恢复与只读检查只记录事实并停止；需要用户再次点击“验证身份并恢复”。网络故障、403、500、截断401、坏JSON和账号不匹配均不会凭空获得新认证资格。
- 已完成回调但尚未被采用的候选，也必须先保存完整会话401或明确匿名响应，下次显式调用才归档并新建候选；不会在同一次点击中循环登录。
- 会话更新证明追加到独立链中，原安全请求的操作身份、请求ID、发送证据、拒绝回执及历史不改写。旧候选先密封归档并读回，再创建新候选；未知的一次性回调状态不能清除或重放。
- 二审发现并修复了“先前因子查询401 → 后续只读检查500”擦除认证依据的问题：只有同账号会话和因子读取均成功，才清除旧拒绝标记。
- 新因子等待激活码单独保持激活提示及输入框，不再被整轮认证运行标志误标为身份验证。

## 第三轮：集成和故障注入

- 协议矩阵覆盖停用/登记两个阶段、三个中断窗口、完整与不完整拒绝、跨步骤/请求再次拒绝后的归档，以及成功收尾清理全部候选。
- 故障注入覆盖会话拒绝保存失败、归档后新候选保存失败、未知回调中断和重启。待保存期间不发送网络请求，存储恢复后先保存最新状态再继续。
