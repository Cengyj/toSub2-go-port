# 账户请求状态统一显示（2026-11-06）

最终显示规则：按用户澄清，每个账号只显示一个最新请求状态，不并列展示多个状态码。

## 原有断点

- 用量摘要只取第一条查询 HTTP 错误，探针只显示一条合并观察。
- 独立套餐刷新、模型目录读取的失败主要留在当次返回中，刷新页面后无法从账号行统一查看。
- 鹈鹕绘图诊断原本仅存在进程内；不同请求来源的失败可能互相覆盖。
- 模型权限正文 `allowed=false` 即使实际 HTTP 200，也被解析层写成了 HTTP 403。
- 部分查询已经收到响应，但在解析、HTML、重定向或读取失败路径中丢失实际 HTTP 状态。

## 实现

公开账号 DTO 增加 `accountRequestObservations`，由 `internal/jobs/account_request.go` 管理并随现有 `job-meta.json` 保存和恢复。控制台的账号列表及详情显式输出该字段。

| 来源 | 内容 |
| --- | --- |
| subscription | 独立套餐刷新、普通查询中的套餐组件 |
| models | 账号模型目录 |
| candy / pelican | 糖果探针、鹈鹕绘图 |
| usage / bps / resetCredits | Codex 用量、BPS 权限、额度重置券查询 |
| authentication / refresh | 登录授权、刷新授权 |
| totp / password / logout | 2FA、密码、退出设备请求 |

### 保存与并发

- 每个来源保留最近一次完整结果批次，同批多个不同错误保留；每来源最多 8 条。
- 成功只替换自己的来源，并保留成功记录，防止旧缓存错误再次出现。同批失败优先于成功。
- 取消、未执行的查询组件、被新授权替代的旧请求不清除原观察。
- 开始时捕获账号实例、创建时间、授权方式、操作次数和操作时间；查询还绑定当次授权预留，写入时在管理器锁内再次校验。
- 请求顺序使用单调递增的本地时间标记，恢复时兼顾已有标记，避免同一时钟刻度或时钟回拨导致旧结果覆盖新结果。
- 诊断不修改账号 `UpdatedAt`、业务状态、操作日志或凭据，不使正常查询预留失效。
- 保存失败只影响展示持久化，不能改变原请求的业务返回值，不能触发重发。
- 不合法的可选诊断条目不会导致整个账号在恢复时被丢弃。

### 真实状态与安全边界

- HTTP 数字只来自实际响应；HTTP 0 表示没有可确认的数字，不显示为 HTTP 0，不推测 401/403。
- `failed + HTTP 200` 表示已收到响应但权限正文、解析或业务确认失败；列表使用“权限受限 / 响应异常”等说明，详情保留 HTTP 200。
- 账号操作通过协议请求回调关联真实响应及返回错误身份；外部邮箱、短信、Sub2API 管理请求不借用账号状态码。
- `ErrSessionExpired` 等明确的认证业务错误可显示授权异常，但不会因此伪造 HTTP 401。
- 保存字段仅含闭集来源、结果、状态码、固定安全分类/文案和时间。URL、响应正文、Cookie、Token、密钥及任意上游错误文字不进入此诊断记录。

### 展示

- 沿用原“已用比例 / 用量”区域的百分比、窗口、重置时间和错误颜色，每个账号最多显示一个最新请求状态。
- 比较请求时间选择最新结果；保留 RFC3339Nano 精度，不能按 HTTP 数值大小或严重程度选择。旧请求较晚返回，不覆盖更新请求的结果。
- 同时间批次按实际观察顺序取最后一条；后端不再按 HTTP 数字排序，重复状态以最后一次位置为准。已被旧版排序写盘的历史记录无法反推原请求先后。
- 最新请求失败时只显示该条错误；最新请求成功时隐藏此前各来源错误，不再回退显示更早错误。底层各来源记录保留，显示规则与存储规则分开。
- 详情同样只说明这条最新结果的来源、状态码、安全原因及时间；429 保持警告色。
- 早于最近一次账号操作的最新可用记录仍标记“上次”，不解释成新授权的实时状态。
- 打开列表、详情不会新增探针、登录、自动重试或独立轮询。
