## 已确认问题与修复

1. **授权到期不能借缓存绕过。** 应用层红测试复现新鲜 normal 缓存仍可能放行已到期授权；现在预检前、使用缓存及返回前核对当前授权和身份。
2. **不完整设置不能静默放宽门禁。** API 直接解码 bool 的缺项/null 会变成 false。复用磁盘严格策略解析器；七类异常请求均拒绝且原策略/版本不变。
3. **回收后恢复不能重放旧检测。** 未取得 jobs 租约的质量排队项不在原用量取消路径内。现在在同邮箱删除栅栏内取消全部历史ID，等待活动探测真正退出；主动提交与回收共用 admission gate。超时保留账号，不宣称移动完成。
4. **最近失败不能显示为当前通过。** 主标题优先显示最新失败、未知、取消、跳过；旧分数明确标历史。过期 normal 显示“历史通过”而非绿色“通过阈值”。数据没有删除。
5. **取消应终止策略锁等待。** 新增带 context 的读取入口，手动/工作流上传与设置 GET 传播当前 context；取消/超时能退出等待，独立写入仍完成。已经开始的 OS 磁盘 I/O 无法被 Go context 强制中断，返回后再次检查取消。

## 上传门禁设计

`Client.Upload → upsertOAuthAccounts` 与 `SyncAccountCredentialsGuarded` 共用授权同步检查。整批账号在任何 Sub2 lookup/write 前完成检查：任一账号被阻止，则本批均未上传。不会偷偷过滤账号后部分上传；用户查看智商列后重新选择。已经执行的探针仍可能消耗额度，零 Sub2 写入不等于零推理。

疑似降智阻止与失败/未知阻止为独立开关。关闭失败阻止不能绕过身份不符、当前授权到期、策略无法读取、结果未可靠保存或取消等安全前提。最新失败/取消不能借更早的 normal 缓存放行。

手动及巡检上传保留账号租约到下游结束；工作流自动上传借用已有所有权，避免重复申请账号锁。缓存绑定授权、账号、代理/TLS、模型、规则与配置；只存摘要和受控结果，不存 token、原始回答或敏感响应。

拒绝时 HTTP 409 返回明确 `outcome=blocked`、`qualityBlocked=true`、`uncertain=false` 和零写入计数。UI 显示“上传已阻止”，保留当前选择与已保存授权，不显示远端失败、部分完成或未知结果，不自动重试。
