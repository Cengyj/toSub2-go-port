# 账号快捷操作与资料卡

2026-10-12，账号操作采用两行三列：第一行为「重登授权」「重置 2FA」「删除」，第二行为「上传」「日志」「更多」。按钮统一图标、文字、边框及底色，下载移入更多菜单。顶部选择数量、本页全选、添加、导入和筛选控件整体靠右，批量按钮位于最右侧，与添加/导入组留出 24px 间距；移除独立工具条，桌面添加/导入与批量操作同行，手机宽度自动换行。账号列仍只显示邮箱、登录方式和套餐，无按钮或垂直分割线。

## 重登后自动上传

单行与批量重登使用相同确认窗口，支持「成功后自动上传 Sub2API」开关。选择保存在当前浏览器的 `tosub2.relogin-workflow-preferences-v1`，清除网页配置时一并删除；只有确认后才执行。未配置 Sub2API 时开关不可用，提供配置入口。

调用 `/api/jobs/:id/relogin` 或 `/api/jobs/relogin-batch`，提交 `uploadAfterRelogin` 和本次使用的 `sub2apiConfig`。管理员密钥仅用于本次流程，不保存到任务持久化数据。重登与上传共用账号执行锁，必须先保存本次生成的新授权，才会上传；已有 Sub2API 账号更新凭证并保持原有配置。

同步结果独立于授权结果：上传失败或结果不确定时，新授权仍可下载，页面显示同步提醒。重启不会自动重复上传；已保存授权但上传尚未执行时显示「同步未执行」。手动上传在当前任务或 2FA 流程未结束、恢复未完成时禁用。

## 账号信息与删除

更多操作中的「查看账号信息」通过受控制台 token 保护、不缓存的 `GET /api/jobs/:id/account-info` 读取当前安全存储资料。展示邮箱、密码、2FA、邮件接口及折叠的代理与收码配置。密码、密钥和接口配置默认不写入 DOM，显式显示或复制后才使用；刷新重新遮盖，关闭取消请求并清空已读取内容。未提交密码、待确认密钥及 OAuth token 不返回。

删除使用现有 `/api/jobs/delete-batch`。删除范围是账号邮箱：同邮箱历史记录、共享密码和 2FA、授权文件一并清理。确认窗口说明范围，前端同步移除同邮箱记录和选择状态；Sub2API 中的账号另行管理。

## 账号到期时间

2026-10-18 新增本地到期管理。账号表格显示完整日期时间、剩余时间／已到期和「手动」「套餐」来源；没有可用日期时显示未知。账号信息中可保存手动时间，或通过「清除手动时间」回退套餐日期。日期是本地使用提醒，不会自动踢出 Team 成员、停用、删除或上传账号，也不改变授权、恢复及套餐排除规则。

导入使用 `----` 显式分隔，在末尾 2FA 后追加日期：

```text
邮箱----密码----2FA----16.30
邮箱----密码----2FA----7-18 08:00
邮箱----密码----2FA----7-18 8:00
邮箱----密码----2FA----2026-12-31 16:30
邮箱----密码----2FA----2026-12-31T16:30:00+08:00
邮箱----密码----邮件收码URL----2FA----16.30
```

`16.30` 与 `16:30` 均表示导入当天 16:30，不是 16 小时 30 分钟后；当天已过去的时间不会顺延到明天。`7-18 08:00` 与 `7-18 8:00` 均表示导入当年 7 月 18 日 08:00，年份按浏览器时区确定，即使该日期已经过去也不顺延到明年。未带时区的完整日期支持 `YYYY-MM-DD HH:mm`、`YYYY-MM-DDTHH:mm`，也可包含秒；日期必须真实有效，不能仅填写日期，非闰年的 `2-29 8:00` 会被拒绝。完整 RFC3339 时间可带 `Z` 或 `+08:00` 等明确偏移。

网页发送当前浏览器的 IANA 时区，后端为整批导入捕获同一个时间基准，再按该时区确定「当天」及「当年」；不受同一批处理跨午夜或跨年影响。显示使用浏览器当前时区，服务端保存 UTC 绝对时间，更换浏览器时区不会改变实际到期时刻。旧客户端未发送时区时使用服务本地时区。夏令时切换造成不存在或重复的本地时间会被拒绝，重复时段需填写带明确偏移的完整时间。这里的时区与 Sub2API 请求时区配置相互独立。

POST 邮件收码继续保留原有请求体语义。在「服务配置」中启用 POST 收码时，新增日期应使用五字段格式：

```text
邮箱----密码----POST请求体或编码请求体----2FA----16.30
```

原有四字段 POST 输入的最后一段仍可作为请求体；不要把普通四字段到期格式直接用于 POST 收码模式。普通格式不提供 2FA 时可保留空位，例如 `邮箱----密码--------16.30`。其他原有无日期格式继续使用。

日期优先级与保存边界：

- 有手动时间时始终使用手动时间，即使它比套餐日期更晚或已经到期。
- 没有手动时间时，只使用与账号身份匹配的授权导出中明确给出的 `subscription_expires_at`。这是真实订阅字段的最后已知快照，不是实时查询，也不是 Token 的 `expires_at`；缺少时显示未知。
- 重复导入省略日期会保留已经保存的手动覆盖；清除是单独、显式的操作，不通过省略字段表达。
- 只修改日期不会读写账号凭据、启动认证 worker 或触发重新登录。到期元数据保存到服务端，刷新页面和重启后的恢复不依赖浏览器偏好。
- 无效日期会在导入提交前报出所在行，错误不会回显该行的密码、2FA 或请求体。保存失败／结果未确认时，先刷新账号信息核实，不能将超时当作确定未保存。

新增持久化字段为可选的 `manual_expires_at`、`subscription_expires_at`；旧数据缺失时仍可恢复，订阅日期可从匹配的现有导出读取。降级到不认识这些字段的旧版本前，按 [安全升级步骤](../go-deployment.md#可重复验证与安全升级) 停止操作并保留整个输出目录的私有快照：旧版本可能在下一次写入 metadata 时丢弃新增日期。不要为恢复日期而覆盖之后已经推进的认证 checkpoint 或凭据；重新升级后可核对快照，仅补回需要的手动日期。

## 重置 2FA 后导出的结论

`TestTOTPResetExportAndAccountInfoUseCommittedFactorAfterCompletionAndRestore` 实际执行合成重置提交与恢复，比较原始信息导出和账号卡返回值：

- 新密钥成功保存并提交后，当前行、同邮箱历史行及重启恢复后的导出均为新密钥。
- 新密钥已提交、后续退出所有设备失败时，仍返回新密钥。
- 旧因子停用前失败时，保留有效旧密钥。
- 正在重置、旧密钥已失效或恢复未确认时，返回 409，禁止输出旧密钥。
