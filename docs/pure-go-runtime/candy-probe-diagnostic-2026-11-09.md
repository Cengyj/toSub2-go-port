# 糖果题探针实调诊断与修复（2026-11-09）

本次按用户要求，对最近失败账号的糖果题实际调用进行诊断。保留工作区已有修改，没有部署、替换运行二进制、重启服务、登录账号、刷新 token 或修改 2FA；没有使用 HAR 或恢复 Cookie。真实请求仅使用该账号已有正常授权及原账号代理，模型 `gpt-6.1-sol`，推理强度 `high`，单次预算 90 秒。

## 实际失败原因

正在运行的 4401 服务对一次完整成功响应误报了“模型回复格式无效”：

1. 上游返回 HTTP 200，完整 SSE 响应结束，但没有 Content-Type 响应头；旧客户端在解析前强制要求 `text/event-stream`，直接拒绝。
2. 同一响应包含已实际观察到的 `response.metadata` 事件；旧解析器未识别该非完成事件，即使通过响应头判断，也会继续拒绝该流。
3. 响应里的 `response.completed`、`object=response`、模型名称、完成状态和最终消息均完整；最终文本为纯整数且与答案 `21` 一致。不是从 HTTP 200 或任意 success 字段推断成功。

诊断只记录 HTTP 状态、正文长度、事件类型/计数、必要枚举、文本长度、是否为整数/预期答案和文件不变性。没有保存或输出完整回答、私有推理、账号邮箱、账号 ID、token、Cookie、代理凭据或原始响应。临时诊断源码已删除。

## 修改与保护

- `internal/modelprobe/client.go`：缺少 Content-Type 时进入严格 SSE 校验；明确的非 SSE 类型仍拒绝。完整响应伴随晚到普通连接错误时，仍必须通过完整终态/身份/输出校验才能采用；取消、超时、超限、不完整响应仍失败。请求保持 `SingleAttempt`，不盲目重放。
- `internal/modelprobe/response.go`：仅将已观察到的 `response.metadata` 加为非完成事件，不保存其内容，不把它当成功证据。支持 SSE 的首部 UTF-8 BOM 和 LF/CRLF/CR 换行。未知事件、失败事件、错误终态、缺少完成、模型不符和矛盾输出继续拒绝。
- `internal/modelprobe/diagnostic.go` 与账号请求/前端：区分 `unexpected_content_type`、`invalid_stream`、`invalid_answer_format`。提示来自固定词表，不回显上游原文。糖果答案规则未放宽，格式错误仍不当作得零分或通过。
- `internal/application/account_quality.go`、`internal/accountquality/runner.go`：账号查询锁占用明确显示 `account_busy`；超时/取消保留已观察的 HTTP 状态，不改写为有效评分，不自动重试。
- `web/src` 探针对话框：读取模型目录时禁用开始按钮，避免模型目录查询与探针争用同一账号；读取完成仍需要用户明确点击。活动任务结束后重新校正不支持的推理强度，保留合法选择。

最新历史记录中另有一次 **0.851 毫秒、无 HTTP 状态的 `probe_failed`**。代码已复现“模型目录读取占住查询租约，糖果题立刻开始”的竞态及其泛化错误显示，但该历史记录没有保留具体原因，不能把它确定归因为账号占用。它与本次已实调确认的 HTTP 200 响应兼容故障分开报告。
