## “推理探针”列表示什么

账号列表中的“推理探针”展示指定模型是否答对内置糖果题。完整整数答案 `21` 记为 `1/1`；其他完整整数记为 `0/1`。当前判定与比分收在同一结果区域内，测量时间、模型、规则版本、耗时和失败原因可在详情查看。排队、运行、失败、未知和历史结果继续区分；未可靠保存的结果显示“保存未确认”。点击结果只打开详情，不发起推理。

**这是固定题目的本地判题，不是标准 IQ、模型排名或上游降级鉴定。** `normal` 表示本次答对，`degraded` 表示本次返回了有效整数但没有答对。输出格式、模型随机行为和所选推理强度都会影响结果；单次回答不能证明模型身份或账号中其他模型的能力。手动“鹈鹕骑自行车”题提供 HTML／SVG 2D 动画供人查看，不计入糖果题分数，也不参与上传门禁。
检测会发送合成提示并产生实际模型推理，可能消耗账号额度、令牌或费用。不能保证每次消耗固定，尤其是较高推理强度。它与[账号用量查询](account-insights.md)的只读信息请求不同。关闭弹窗或取消本地等待不能保证撤销已经被上游受理的推理及其额度消耗。

## 规则与协议边界

规则版本为 `candy-v1`，完整提示和本地评分见 [rules.go](../../internal/modelprobe/rules.go)。糖果题与用户指定的 [ranxi2001/sub2api](https://github.com/ranxi2001/sub2api/blob/b50754c0facddce08ef13900dfc1302061d1710b/backend/internal/service/pelican_scheduled.go#L19) 内置题一致：

| 形状 | 苹果味 | 桃子味 | 西瓜味 |
| --- | --- | --- | --- |
| 圆形 | 7 | 9 | 8 |
| 五角星形 | 7 | 6 | 4 |

可凭手感分辨形状，并在活动前决定每种形状的取数。要求保证拿到不同形状的苹果味与桃子味配对。标准答案为 **21**：取 9 颗圆形和 12 颗五角星形；9 颗圆形必有苹果或桃子，12 颗五角星形必同时有苹果和桃子，因此能组成异形配对。本地测试枚举六格糖果数量，验证不存在更少的固定形状配额能保证成功。题义允许按形状选择；若完全随机盲抽、不区分形状，结论不同。

回答必须是完整、规范的非负十进制整数，仅允许前后空白。`21` 为 `1/1`，`29` 等其他整数为 `0/1`。解释、JSON、Markdown、前导零、负数、空串、拒答、超时或未完成输出属于失败或未知，**没有分数**，不会伪装成 `0/1`。旧六题结果保留历史，但因规则版本与配置摘要变化不能作为新规则的通过缓存；读取旧策略时将原 1–6 的阈值在内存中归一为 1，不改原开关、不自动写文件或递增 revision。

支持两条独立授权路径：

| 已保存授权 | 固定推理端点 |
| --- | --- |
| ChatGPT / Codex | `POST https://chatgpt.com/backend-api/codex/responses` |
| BPS | `POST https://bps.openai.com/basispoints/api/responses` |

两者均读取与当前账号匹配的 OAuth access token 和账号 ID，不登录、不刷新令牌、不修改 2FA，不转用其他授权。一次请求提交一道糖果题，`stream=true`、`store=false`，不启用工具。只有确认 SSE 完整结束、终态为 completed、返回模型与所选模型相符、输出结构有效且流式片段相互一致后，才评分。HTTP 200、`[DONE]`、一段文字或部分输出均不足以判定完成。日期版本模型名可匹配所选基础名称；其他模型被拒绝。

BPS 使用其原生白名单字段：明确模型 `model_selection=explicit`、developer/user 消息、`reasoning_effort`、独立请求标识和上下文配置。它带选中 BPS 授权的 Bearer、两个账号 ID 头、`X-Basispoints-Auth-Mode=chatgpt`、BPS Origin 及 Excel 产品／profile 头；不携带 Codex Cookie、Originator、工具声明、函数 schema 或 Codex `reasoning` 字段。`none/minimal` 映射为 `low`，`max/ultra` 映射为 `xhigh`，空值按 `medium`；其他已支持等级保持。 原生 BPS 可省略 `response.object` 与消息 `status`；仅允许缺省，显式字段仍须分别为 `response`／`completed`，终态事件、响应 status、id、model 和文本一致性检查保持。BPS 单账号、所选、全部和上传前检查均使用相同资格、租约与缓存规则，不再按授权类型直接标为“不支持”。

网络层使用现有 Go transport，每次 POST 标记为 `SingleAttempt`。不重试、不跟随重定向、不重放 challenge、不跨账号或跨授权端点降级；调用受 context、超时和响应上限约束，糖果题为 1 MiB，手动绘图为 16 MiB。BPS 原生 schema 不发送 `max_output_tokens`。取消或结果未知后再次检测属于新的推理请求，可能再次消耗额度。

上述实现不保证每个账号拥有填写的模型及推理强度权限；401、403、限流、网络和未完成输出按真实失败显示。探针模型与 BPS 上传模型配置、映射和“对所有模型启用”语义独立，不修改上游权限。

## 账号列表与探针入口（2026-11-07）

账号列表保留推理探针列和表头，不显示彩色历史方块或装饰图标。按用户最新“不希望空白”的要求，列内改为可读状态文字与中性细轨道：尚未检测、等待数据、检测中、失败或已有结果均有明确说明。功能启用时保留 9 列布局，关闭时为 8 列，空态和展开日志跟随实际列数。用量采用同一状态视觉语言，真实比例仍按原进度条显示。设计与边界见 account-metric-states-2026-11-07.md。

探针功能继续可用：账号“更多”菜单保留“推理探针详情”和“发起推理探针”，原批量操作、服务配置及上传前检查均保留。用量列继续接收探针的最新 HTTP 观察。

安全的历史摘要保存在原账号快照中，可在重启后恢复；历史不参与评分、上传门禁或重试。旧数据不补造多次记录。实现边界和验收见 `usage-probe-history-2026-11-06.md`。

## 账号模型目录（只读）

`GET /api/account-quality/models?id=<账号ID>` 按所选账号的已保存授权读取当次模型目录。此接口在探针总开关关闭时也可使用；它只发送一次 GET，不发起糖果题或绘图，不登录、不刷新 token，不写账号操作历史、检测结果、设置、授权文件或上传模型映射。读取期间使用现有账号查询租约，授权或代理改变后丢弃过期响应。

| 已保存授权 | 官方目录 | 响应 `source` |
| --- | --- | --- |
| ChatGPT / Codex | `GET https://chatgpt.com/backend-api/codex/models?client_version=0.155.0` | `codex-models` |
| BPS | `GET https://bps.openai.com/basispoints/api/responses/access?include_models=true` | `bps-access` |

成功响应包含 `models`、`source` 和 `fetchedAt`；每个模型提供 `id`、`displayName` 与上游声明的 `reasoningEfforts`。BPS 复用账号用量查询的目录解析器，排除受限制、明确不可用、picker 关闭或策略禁用的模型。Codex 保留目录返回的有效模型，包括 `visibility: hide` 或 `model_picker_enabled: false` 的条目；这两个字段控制官方客户端选择器展示，不代表调用权限。只排除明确 `available: false`／`enabled: false` 的条目，转换方式参考 [sub2api 的 Codex manifest 投影](https://github.com/ranxi2001/sub2api/blob/b50754c0facddce08ef13900dfc1302061d1710b/backend/internal/service/openai_models_list.go#L114)。实时条目没有声明推理强度时返回空数组，不凭模型名称推测账号权限。

目录请求的 `client_version`、`Version` 与 `User-Agent` 版本统一采用 `0.155.0` 兼容基线。[官方模型描述](https://github.com/openai/codex/blob/b1e72963c3b71a9265a551e54beff078384efed9/codex-rs/models-manager/models.json) 中 GPT-6.1 Sol／Astra 声明最低客户端版本 `0.153.0`，GPT-6 Sol／Luna 声明 `0.155.0`；先前固定的 `0.146.0` 低于这些要求。目录版本协商与展示字段过滤分别处理，不改变已保存账号授权或模型配置。

Codex 成功响应另有可选 `suggestedModels`，提供账号目录未列出的常用模型；两类在 API 与页面状态中分别保存。选项参考 [sub2 默认模型](https://github.com/ranxi2001/sub2api/blob/b50754c0facddce08ef13900dfc1302061d1710b/backend/internal/pkg/openai/constants.go#L23) 与用户指定模型清单，包含 GPT-6.1 Sol／Terra 等。实时条目排前，常用条目带来源标记，选中后说明未列入账号目录；不要求用户手输 ID。按所有已返回 ID 去重，因此明确禁用的模型也不会被常用选项重新加入。GPT-6.1 Sol 的强度参考嵌入官方描述（low／medium／high／xhigh／max／ultra），Terra 参考 sub2 的配置选择（none／low／medium／high／xhigh／max）；这些是模型预设能力，不是账号权限验证。BPS 不提供这组补充项。

有效的空目录返回 HTTP 200、`models: []` 和空目录说明，Codex 的常用选项仍独立可选；查询失败返回非 200、安全错误说明、稳定 `code`，必要时附上游 `httpStatus`，并清空旧实时与常用选项，不以预设伪装成读取成功。不使用 BPS 上传映射或旧目录补充权限。模型目录与常用选项均不等于已经验证推理成功，实际调用仍按提交时的上游结果处理。请求有独立超时和 1 MiB 上限，不重试、不跟随重定向、不跨授权路径降级。

## 探针卡片交互（2026-11-05）

卡片统一为题目、可搜索模型、推理强度组成的参数区，以及操作条、结果区和折叠详情，不使用题目页签。桌面三项同行，窄屏题目独占一行；长账号与模型有省略和完整标题提示。模型菜单支持搜索、方向键、Enter、Escape、自动滚动当前项，并按可视高度选择展开方向。读取目录失败或为空时如实提示，保留重读和显式输入入口。

单账号糖果检测的 `POST /api/account-quality/refresh` 与手动绘图的 `POST /api/account-quality/manual` 支持可选 `options: {model, reasoningEffort}`。省略沿用已保存全局配置；提供时须完整包含两个字段。本次选择不写全局模型、上传策略或 revision，执行及缓存绑定本次参数；在途不同参数不合并，手动同 requestId 更换参数返回冲突。设置页选择仅更新草稿，点击保存后才更新默认策略。

参数不同的有效测量保留实际分数与模型，详情明确说明不用于默认上传策略。快照的 `staleReason` 区分 `expired`、`account_unavailable`、`authorization_changed`、`rule_changed`、`options_changed`，只有实际超时才显示“已过期”；上传门禁的严格校验保持。运行、提交或结果待核实时锁定题目和模型，未知结果只读取核对，不自动重放。

本轮合成截图及交互回执见 `ui/probe-layout-20261105-*`，覆盖宽屏、390/320px、低高度键盘长列表、绘图、取消、空/失败目录、单次参数与设置草稿。合成推理仅在 fixture 执行，不使用真实账号额度。

失败时结果卡直接展示原因、错误码和已取得的响应 HTTP 状态；账号行显示“查看错误详情”，点击即可打开。失败不会显示为待开始空态，上次有效成绩单独标明，本次失败卡使用本次尝试时间。手动绘图采用相同错误组件；没有具体消息时也能查看已保存的错误码和中文兜底原因。

`lastAttempt.httpStatus` 与手动记录的 `httpStatus` 为兼容新增字段，只保留真实取得的 100–599 状态。流式或格式校验失败可能同时显示 HTTP 200，它只表示上游 HTTP 响应成功，不表示检测通过。旧记录没有保存该字段时不补造状态，也不重新执行推理取得错误信息。诊断只使用有限中文分类，不持久化凭据、请求头或原始上游正文。合成失败卡证据见 `ui/probe-errors-20261105-*`。

探针取得的 HTTP 401、402、403 等错误同时显示在“已用比例”列，使用危险色；HTTP 429 显示“HTTP 429 限流”，在用量列、用量详情和探针结果中统一使用提醒色。它表示请求限流，不推断账号封禁、授权失效或欠费。点击用量可查看糖果探针／鹈鹕绘图来源、观察时间及安全原因。实际用量百分比和下一次重置时间保持原值，两个额度窗口继续上下排列。查询与探针相同状态码在账号行合并并保留来源说明，不同状态码同时展示。

批量 `GET /api/account-quality?ids=...` 的 `snapshots[id].httpObservation` 为可选字段，包含 `status`、真实取得时的 `httpStatus`、`errorCode`、安全 `message`、`finishedAt`、`source: candy|pelican` 与 `model`。服务端从自动糖果与手动绘图中选择最新的明确观察，绑定当前账号授权与传输身份；授权变化或账号不可检测时隐藏。完整成功可清除此前的探针 HTTP 错误，排队、执行、取消、无响应和 HTTP 200 格式错误保留此前明确观察。用量查询成功不会清除探针错误，探针成功也不会清除独立的查询错误。

自动观察单独持久化并保存自身身份修订，不借用新任务的修订；旧记录仅在身份仍匹配时只读回填，未保存 HTTP 数字的旧分类只显示“权限受限／授权异常／限流”。手动观察随进程保存在内存中，不修改自动分数、上传门禁或用量缓存。回收期间隐藏观察；同授权恢复后可继续显示带来源与观察时间的记录。网页读取不触发模型请求、重试或每账号手动状态轮询。合成视觉与交互证据见 `ui/usage-http-20261105-*`。

## 使用入口与配置

在“服务配置 → 推理探针”选择模型目录来源账号，再搜索选择检测模型并保存。未提供目录时可切换账号或使用“输入模型”手动指定。配置属于本地服务，由使用该服务的浏览器共享；刷新、关闭网页或更换浏览器不会清除已保存策略。“清除网页设置”只处理浏览器偏好，不删除这份服务端策略。未保存草稿不影响运行；读取冲突或保存结果待核实时，应先重新读取、核对，再明确保存。

| 配置 | 默认值 | 含义与范围 |
| --- | --- | --- |
| 启用推理探针 `enabled` | 关闭 | 未启用时不发起新检测，历史测量仍可查看 |
| 上传前检查 `beforeUpload` | 关闭 | 只有它与总开关同时开启，上传才进入检测策略 |
| 检测模型 `model` | 空 | 启用时必须明确选择或输入账号可调用的模型名称，最长 128 字符 |
| 推理强度 `reasoningEffort` | `high` | 支持 `none/minimal/low/medium/high/xhigh/max/ultra`；目录声明了强度时按模型筛选，是否可用由上游模型决定 |
| 通过阈值 `minimumScore` | `1` | 固定为一道糖果题答对；不再提供六题阈值 |
| 糖果题超时 `timeoutSeconds` | `90` 秒 | 1–300 秒，外层任务更短的取消期限仍有效；手动绘图独立使用 300 秒 |
| 重复检测冷却 `cooldownSeconds` | `60` 秒 | 0–86400 秒；冷却不是自动重试计划 |
| 结果有效期 `resultTTLSeconds` | `900` 秒 | 1–86400 秒；还必须满足相同授权、传输身份与规则等校验 |
| 低于阈值时不上传 `blockDegraded` | 开启 | 仅对得到有效分数但低于阈值的结果生效 |
| 检测失败或结果未知时不上传 `blockFailed` | 开启 | 对允许按失败策略处理的探针错误生效 |

默认总开关和上传前检查均关闭，因此不会因为新增功能自动推理，也不会仅因两个阻止策略的默认值为开启就改变旧上传行为。启用后没有定时模型检测；网页读取状态和轮询不会自行产生推理请求。

主动检测入口保留在详情中的“发起推理探针”、账号“更多”以及工具栏的“所选账号探针”和“全部账号探针”；账号列内不重复放置发起按钮。点击结果只打开详情，不产生推理请求；关闭、冷却、排队、失败和 BPS 账号仍可查看详情。只读结果区域为单一原生按钮，保留不少于 28px 高的交互范围与键盘焦点反馈；Escape 关闭详情后回到原入口。“所选”使用当前选择的账号 ID；“全部”覆盖活动账号，不受当前分页或筛选限制，仍由后端按资格、账号互斥、去重和冷却受理。提交回执中的 accepted、merged、skipped 分别表示新受理、合并已有请求和跳过，不能当作检测完成。

详情区区分未检测、排队、检测中、完成、失败、取消和跳过，并展示最新尝试原因。关闭详情只关闭界面，已经受理的检测继续执行；需要停止时使用“取消检测”。失败或取消后，最近有效测量作为历史保留，并同时说明最新尝试的真实状态。

## 手动检测：鹈鹕骑自行车

打开账号的推理探针详情后，在“检测题目”中选择“鹈鹕骑自行车 · 2D 动画”，选择模型与强度，再点击“开始手动检测”。该固定题与目标 sub2api 项目一致，要求创建以 SVG 绘制的鹈鹕骑自行车 HTML 2D 动画，直接交付无外部依赖的独立 HTML。ChatGPT 与 BPS 均使用本次选择的模型和推理强度，以及全局冷却和已保存授权。绘图使用独立的 300 秒（5 分钟）超时，不沿用糖果题默认的 90 秒；页面提示绘图通常约需 3 分钟。主动取消、服务关闭和授权失效仍可提前终止，超时不自动重试。打开详情、切换题目和读取结果均不发送推理请求。

手动结果与糖果题评分、上传前缓存完全独立，不会将绘图成功当作推理通过。最多一个手动任务同时执行；请求 ID 在 24 小时内去重，失败或响应丢失不自动重试。任务受账号租约与服务生命周期管理，取消、回收账号或关闭探针会结束活动任务；关闭详情窗口只停止页面读取。聚合探针状态包含手动活动数，部署前须一并排空。

绘图 SSE 流有独立的 16 MiB 响应预算，覆盖传输读取、返回体检查、解析器和单行扫描，容纳推理事件、文本增量及终态重复文本。仍须收到完整且一致的 completed 终态；超限或截断不会截取部分 HTML，也不会自动重试。最终 HTML／SVG 文档上限为 2 MiB，旧静态 SVG 兼容字段保持 256 KiB 上限，糖果题仍使用 1 MiB。

生成作品仅保存在当前服务内存，每账号保留最近一份；重启后不保留。后端校验完整文档边界与大小，保留动画所需的内联 CSS 和脚本。前端使用 `sandbox="allow-scripts"` 的独立 `iframe/srcdoc`，不允许同源访问，CSP 禁止外部网络资源。作品按比例适应预览区域，并提供放大、原始大小、查看源码和下载原始 HTML。旧静态 SVG 只作为兼容输入，刷新页面不会把它改成动画，需要用户明确重新检测。手动开始／读取／取消分别使用 `POST /api/account-quality/manual`、`GET /api/account-quality/manual?id=...` 和 `POST /api/account-quality/manual/cancel`。

早期静态 SVG 的合成验证见 `ui/candy-bps-20261105-*`；HTML 动画预览的合成验证见 `ui/pelican-html-20261105-*`。两者属于不同展示版本，不能以旧版静态图片证明当前动画实现通过。

## 上传前的两项独立策略

手动上传、重登后上传、2FA 后上传和巡检凭据同步共用应用层门禁。原有授权有效性、账号身份、套餐排除和上传字段合并规则仍需通过；模型检测不会取代这些规则，也不会清除已经安全保存的授权。

在检测功能和上传前检查均开启的前提下：

| 预检结果 | 控制规则 |
| --- | --- |
| 有效分数达到阈值 | 此项检测通过，随后继续其他上传校验 |
| 有效分数低于阈值 | 由 `blockDegraded` 决定是否阻止 |
| 探针网络失败、超时、输出不完整、不支持等可配置失败 | 由 `blockFailed` 决定是否阻止；不会制造通过结果 |
| 账号/授权身份不符、已知授权到期、401、缺少授权、代理身份未确定、无安全 transport、非法配置、重定向 | 安全前提不成立，不能靠关闭失败策略放行 |
| 策略不可读取或持久性未确认、结果未可靠保存、账号忙、取消、授权或策略已变化 | 暂停本次上传，核实后再操作 |

两项阻止策略互不替代。关闭“低于阈值时不上传”不会同时允许超时或未知；关闭“检测失败或结果未知时不上传”也不会允许身份不符、到期授权、未可靠保存的结果等安全前提失败。允许某类失败只表示用户选择继续既有上传流程，界面仍保留该错误，不能改写为“检测通过”。

批量上传在任何 Sub2API 远端请求之前进行整批门禁检查。任一账号被策略拒绝，当前批次均不开始 Sub2API 请求；不会自动剔除失败账号后上传其余账号。用户应核对账号列与详情，再明确重新选择上传范围。**零 Sub2API 请求不等于零上游推理请求**：前面已执行的探针可能已经消耗额度。预检通过后的远端更新、创建和结果未知仍遵循原 Sub2API 同步语义，本功能不把远端失败改写为成功。

未装配检测 controller 的独立上传入口也会读取持久策略。仅在策略确实缺失或有效关闭时保留旧上传路径；已启用上传门禁、策略损坏或无法可靠读取时，不能静默绕过。

## 账号锁、缓存与重启

主动检测取得已有账号查询租约，与同账号登录、重登、刷新和安全操作互斥。手动上传会把租约保留到下游上传结束；新账号操作可取消整个上传 session，并等待旧租约退出后开始。工作流内的自动上传借用它已经持有的账号所有权，不递归申请同一把查询锁。调用方取消、服务停机和 session 取消会传播给探针；迟到结果还要复核身份才能采用。

缓存绑定已提交授权、账号身份、账号修订、有效代理/TLS 身份、所选模型、推理强度、阈值、规则版本及其配置摘要。只保存摘要，不保存 token 或代理凭据。授权替换、代理/TLS 变化、配置变化或超出有效期时，旧观察不能充当当前通过依据。即使通过结果还在 TTL 内，当前授权已知到期也会阻止上传。

上传只能复用已可靠持久化、仍有效且最新尝试成功的匹配结果。**新尝试失败、取消或被取代后，不能借用更早的通过结果放行。** 最近有效结果仍可作为历史展示；历史展示与当前门禁资格是两件事。缓存读取损坏时保留原文件并显示不可读取，不以空记录或默认正常覆盖。

重启不会自动重放上次排队或执行中的推理。这类记录标为已中断/取消，用户可在核实后重新提交。已完成历史结果仍按当前身份和策略重新校验，不能仅因磁盘上有一个 normal 就视为可复用。

## 数据位置、权限与回收站

新增数据位于现有私有数据根之内：

```text
<data-root>/account-quality/settings.json
<data-root>/account-quality/<sha256-of-job-id>.json
```

策略包含版本、revision 和显式开关；观察文件包含规则结果、最近尝试、安全错误分类、时间、账号修订与身份摘要。它们不包含 OAuth token、密码、Cookie、完整模型回答或提示回放日志。账号 ID 和运行信息仍属于私有数据，不能因为文件名经过哈希就公开或加入 Git。

文件沿用私有原子写入机制。Unix 系统目录要求 `0700`、私有文件要求 `0600`；Windows 使用现有私有 ACL 规则，并拒绝不满足规则的目录/文件和重解析路径。读取会检查普通文件、大小、身份、权限和 JSON 结构，不在只读判断时修复不可信权限。平台代码存在不代表已经完成本轮 Windows 原生验收。

只有策略文件真正不存在且没有已知持久化失败时，运行中的服务才可使用关闭的默认策略。已存在策略中的缺项、重复字段、null、无效版本/范围或权限异常不会被当成 disabled。保存替换已发生但持久性未确认时，先核实实际文件和存储状态，再明确保存。不要通过删除设置文件来“修复”错误：新进程可能因此采用关闭默认值，丢失原上传阻止意图。

账号移入[回收站](recycle-bin.md)时保留模型检测历史，回收账号不再具有主动检测资格；重启也会读取受保护的历史 ID。恢复不会重放原检测，旧结果继续接受账号修订与授权校验。

明确永久清理进入 `purging` 后，共用清理路径删除对应账号的哈希观察文件。仍活动的账号、未退出的检测或缓存删除/持久化失败会阻止宣称清理完成，并保留可重试的回收条目；不会把这些失败当作成功清空。永久清理单账号不删除全局检测策略，也不删除其他账号观察。

## 构建、升级与恢复

沿用现有纯 Go 单体服务、Go esbuild API 和受控 `web/vendor` 前端构建。认证动态 JavaScript 仍由 Go 内嵌 Sobek 执行；本功能没有新增 Node、Python、Chromium、外部评分服务或浏览器登录路径。构建及运行步骤见 [README](../../README.md)、[运行配置说明](../../README-Go.md) 和[部署说明](../go-deployment.md)。

升级前建立维护窗口并阻止新任务进入，排空账号任务、上传、模型检测、用量查询、巡检与回收清理。关闭检测服务会拒绝新任务、取消已受理检测，并等待运行与已受理写入退出；超时或取消错误不能当作安全停服完成。确认进程退出后，保存旧二进制、嵌入前端资源摘要和配置，再备份同一时间点的整个数据根。

备份应包含 `account-quality/`，以及 `job-meta.json`、账号目录、checkpoint、当前授权结果、回收站和用量缓存等现有文件；平台安全凭据及恢复材料按原存储规则一并保护，不导出为明文。示例备份位置为 `<private-backup-root>/before-upgrade/`，保持私有权限，并单独验证复制完整性。

恢复时先停服并保留当前完整副本，再整体恢复一致的元数据、策略、账号文件和所需安全凭据。不要用旧通过缓存搭配新账号文件，也不要为修复模型检测而覆盖升级后取得的一次性授权、刷新结果或新 2FA 密钥。先用合成账号与独立临时目录验证恢复流程；真实数据不用于探针或迁移实验。

升级后只读核对服务健康、实际运行二进制与前端版本、检测设置和账号状态。查看页面或读取状态不需要触发真实模型请求；真实模型可用性和计费结果不能由合成协议测试代替。

## 回退与卸载

**不认识上传门禁的旧版本可能直接忽略 `account-quality/settings.json`，继续上传原本应阻止的账号。** 保留策略文件或成功启动旧二进制都不能证明策略仍生效。应优先选择保留门禁契约的兼容版本；若确需跨功能版本回退，必须在维护窗口内明确核对上传行为变化，并保留当前完整备份。不能通过悄悄删除目录或仅替换二进制来宣称安全回退。

回退还要满足[回收站格式与暂停标记的限制](recycle-bin.md#回退限制)。恢复升级前完整备份会舍弃之后的变化，应单独确认影响，不将新旧元数据、授权、凭据和缓存随意混搭。

普通停止或移除程序保留数据。关闭检测开关保留策略和历史；删除缓存也不等于卸载账号或销毁凭据。彻底卸载按[本地卸载说明](../local-macos.md)停服、解除自启动，并处理完整数据根（包括 `account-quality/`）、对应安全凭据 namespace、另存备份与导出。不要使用单账号永久清理删除全局策略，也不要把清除浏览器偏好当作服务端数据已删除。
