## 范围与证据

本轮继续基于上一轮刷新生命周期的工作区修改，不回退既有成果。目标是让用户看清哪个账号仍在排队、哪个账号正在查询，同时消除批量按钮旁与顶部重复的数量说明。

已确认的原因：

- `web/src/components/account-usage.jsx` 先前把 queued/running 等尝试状态放入 `aria-label`，可见区域只展示缓存窗口或未知占位，因此视觉上无法辨认正在刷新的账号。
- `web/src/main.jsx` 的 `selected-insights-refresh-description` 作为可见文本重复了顶部查询数量，并额外使用 `role=status`。
- `LastAttempt` 表示查询记录，不是任务占用的唯一依据：授权身份变化可能重置历史投影；查询结果写回后，运行任务还可能处于资源释放阶段。

## 展示与状态契约

| 当前账号 | 可见反馈 | 数值与业务语义 |
| --- | --- | --- |
| 有数值用量，排队 | 时钟、等待刷新、保留上次用量 | 原百分比、重置时间与观察时间保持不变 |
| 有数值用量，执行 | 旋转图标、正在刷新、保留上次用量 | 用量条继续表示额度已用比例，不表示查询进度 |
| 无有效数值，排队 | 等待查询、等待结果说明 | 不产生 0% 或虚构的数值条 |
| 无有效数值，执行 | 正在查询、旋转图标 | 已知 BPS 权限及未知窗口仍保留 |
| 完成、失败或取消且任务已释放 | 退出刷新提示 | 保留有效历史观察及既有错误表达 |

顶部“账号状态与用量”集中展示查询汇总。所选刷新按钮保留直接入口、忙碌/禁用状态、提示及无障碍描述；旁边不再重复显示整串计数。账号行不新增 live region，避免轮询时反复播报。查询中仍可打开详情。

没有提供队列序号、预计耗时或查询完成百分比：调度器没有这些可靠数据。已有用量 `usedPercent` 不能用于推测查询完成度。

## 实现边界

- 后端公开投影新增可选 `Snapshot.refreshState`：`eligible / queued / active / coolingDown / unavailable`。直接复用 `refreshStateLocked`；与全局及所选范围的资格判定同源。
- 该状态读取时计算，不改变调度、授权、历史结果或正常缓存格式；任务资源释放前保持 active。
- 前端优先使用明确的 `refreshState`；旧服务缺少该字段时兼容既有 `LastAttempt`。明确的非活动状态覆盖旧尝试记录，普通页面轮询不视为上游查询。
- 详情的取消入口和单账号提交门禁使用同一状态派生；未知值不能放行，`eligible` 仍需 `canQuery=true` 及已确认的全局状态。原同帧防重复和受理后重新核对屏障保持。
- 样式只使用现有主题变量，遵从减少动态效果设置。
- 删除 `.refresh-scope-hint`：唯一 DOM 使用点改为现有 `.sr-only`，该可见布局规则已无用途。没有删除业务流程或测试。
