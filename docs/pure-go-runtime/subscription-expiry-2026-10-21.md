# 套餐到期日期解析修复（2026-10-21）

## 已确认原因

本轮以现有工作区及全部未提交改动为基线。只读检查本地已保存的 OAuth 导出，在内存中解码并仅输出订阅日期字段：实际存在 `https://api.openai.com/auth.chatgpt_subscription_active_until`，旧代码却只识别 `subscription_expires_at`。因此即使授权里带有订阅截止时间，导出、任务恢复及页面也会显示未知。检查没有输出 token、账号标识、密码或 2FA 密钥，也没有触发真实认证或远端更新。

另外，以合成数据确认了两个独立缺口：

- 同一 workspace 的套餐发生变化时，旧 ID token 的日期可能被继续使用；明确 null/空/无效日期也没有与“未提供字段”区分。
- 手动导入的 `7-18 08:00`、`7-18 8:00` 未进入到期解析；前端 JavaScript Date 会将非法日历日期归一成另一天，或将无时区字符串当作本地时间。

## 当前规则与实现

1. `internal/protocol/oauth_metadata.go` 同时识别规范字段和真实 `chatgpt_subscription_active_until` claim，按 access token 优先、ID token 兜底读取，统一为 UTC RFC3339Nano。只读解码用于显示元数据，不作为认证或授权依据。
2. workspace 或明确套餐不一致时不借用旧 ID 日期。`SubscriptionExpiryReported` 区分未提供、有效值及明确未知；新授权始终先保存，元数据异常不会丢掉已轮换的 token。
3. 刷新时，同 workspace/套餐且未提供日期可保留已确认信息；明确未知则清除旧日期。导入身份别名也参与 workspace 变化检查，并随新身份同步。
4. `internal/jobs/expiry.go` 在旧导出缺少规范日期字段时，从其自身已保存的 token 补读，检查明确身份和套餐是否匹配。恢复不修改授权文件、不访问上游、不排队登录，手动时间继续优先。已有明确导出字段（包括未知）优先于旧 token 兜底。
5. 上传规范化支持同样的字段来源；明确未知可清除远端旧订阅日期，但保留模型、时区、分组等既有配置。此路径仅用模拟服务/合成数据验证，没有执行真实上传。
6. `internal/accountplan.FromExplicitAccount` 仅检查明确导出套餐，避免校验新 access token 日期时再被旧 ID token 的套餐反向覆盖。既有套餐排除决策未改为另一种来源优先级。
7. 前端只接受有效且带时区的持久化日期，并在浏览器本地时区展示。手动 `16.30`/`16:30` 使用导入当天；`7-18 08:00`/`7-18 8:00` 使用浏览器时区的导入当年，已过日期不顺延。完整日期时间、DST 歧义拒绝及手动优先规则保持。

以下字段不能用于推算套餐到期：OAuth `exp`/`expires_at`/`expires_in`、订阅开始时间、最后检查时间。未返回真实截止日期的账号继续显示未知；Team 成员仍可能在套餐截止日期之前被移除，该日期不承诺成员资格有效期。
