# 上传审查与首次手动上传修复（2026-11-14）

本次覆盖手动单条/批量 Sub2API 与 CPA、重登和 2FA 后自动上传、号池修复，以及相关配置、授权文件和回执。未确认可利用的安全漏洞；没有连接真实 sub2、使用真实账号或部署服务。

## 首次手动上传失败

浏览器将号池 ID 保存为文本，并把代理 ID、并发、负载和优先级的空白值保存为 `""`。手动上传以前直接把这些值放入新建账号请求。要求整数的服务器会拒收，即使用户使用默认空白配置也可能失败。已有账号的授权更新不发送这些路由字段，因此不同账号可能表现不同。

隔离测试用严格整数管理 API 复现了两种失败：空白默认配置和填写了数字的配置均返回 HTTP400，账号未创建。该缺陷与历史反馈吻合，但由于当时的上传回执不明确，不能断言它解释了历史请求的全部情况。

现在手动上传与自动上传共用 `ParseUploadSettings` 和 `BuildUploadPayload`：数字文本转换为整数，空白选项不覆盖，显式零值保留；小数、负数、溢出和非法配置在请求服务器前拒绝。未知业务字段继续保留 JSON 数字精度。更新已有账号继续保留远端号池和路由设置。

## 上传边界

- 手动 Sub2API 使用有界、私有、已提交的授权文件；恢复日志、符号链接、不安全权限和过大文件会阻止上传。
- 旧 `sub2api-data.json` 仅在当前文件缺失时兼容读取，并接受同样校验；当前文件读取失败不会回退。准备旧文件后若出现当前文件，停止此次上传。
- 获取账号租约后及写入前核对原始文件字节；监控同步同样复核。授权文件变化或刷新结果待保存时停止后续发送。
- Sub2API 查询后、每次更新以及整批新建前重新检查授权策略；中途拦截保留已经完成的条数和未执行条数。
- 失败提示区分上传资料校验、远端查询、目标身份和授权复核，保留安全 HTTP 状态和 2FA 恢复指引，不显示上游正文或凭据。
- 地址拒绝末尾裸 `?`，防止后续 API 路径被当成查询参数。未知修改结果不自动重试。

授权保存成功与远端同步成功仍为独立结果。没有收紧尚未核实的 Sub2API 旧版本修改回执格式。
