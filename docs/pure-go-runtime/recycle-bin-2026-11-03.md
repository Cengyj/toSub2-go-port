日志“完整”指所有目前仍存在的记录及本轮之后的新历史。旧版本已经截断、磁盘也没有的日志无法补回。归档失败时不裁剪未保存记录，也不把回收宣称为成功；不会为了通过测试丢弃旧日志。

最终交叉检查补充修复两处永久清理边界，并先用回归复现失败：

- 同邮箱只有 `totp-setup-result.json` 的未索引恢复目录也必须先加入持久墓碑，否则清理完成后重启可能重新发现账号。识别遵循现有启动恢复的优先级和邮箱规范化，并拒绝通过符号链接认领其他资料。
- 扫描额外目录与写入墓碑之间，显式 ID 导入可能取得相同 ID。现在在写入墓碑的同一锁内重新检查 active 和其他 trash 所有权；冲突不改墓碑，避免新账号被隐藏进不可恢复清理状态。

新增回归包含 TOTP-only、不同邮箱、非重置结果、符号链接和两类新所有者冲突。仅局部增强 `internal/jobs/trash.go`，没有更改原恢复语义。
