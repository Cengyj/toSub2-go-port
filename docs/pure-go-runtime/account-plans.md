## 套餐来源与范围

- 从已有 `sub2api-import-oauth.json`、`sub2api-data.json` 的账号元数据及 OAuth ID/access token 套餐 claim 中提取；导出需与任务邮箱匹配。公开 API 只返回规范化的 `planType`，不返回 token 或其他私有 claim。
- 恢复任务、发现新输出及保存登录/刷新结果时更新套餐，页面轮询只读缓存。缺少新 claim 时保留此前已知套餐。只包含 session、未包含这些 OAuth 导出的任务可能显示未知。
- 套餐表示最后可用授权/元数据的快照，不是实时订阅查询。显示套餐不会主动登录或访问上游。
- 入队时，任一本地已知套餐或 Sub2API 远端已知套餐命中排除，就跳过该邮箱的自动重登；不再用一个来源覆盖另一个来源的排除证据。启用排除时读取全部 OpenAI 记录，以保护同邮箱下其他号池或正常状态的已排除套餐；自动修复候选仍只包含目标号池的异常记录。
- 队列执行前根据最新本地套餐和当前排除策略再次检查。被排除的队列项不执行登录，账号行显示“自动重登已跳过”及具体原因，已有授权和恢复数据保留，不把跳过当作完成或失败。关闭监控、切换后端或重启旧自动队列也可能导致跳过，因此账号行不会仅凭 `skipped` 推断为套餐排除；巡检统计中的“按套餐跳过”只表示实际套餐排除。
- 自动授权完成后，如果新的本地套餐命中排除，暂停自动回传；新授权与待处理 ID 保留。账号行显示“授权已保存 · 自动回传暂停”，巡检结果单独计数，不能据授权步骤成功认定 Sub2API 同步完成。
- 手动重新登录和手动上传仍允许。暂停自动回传后可在账号行点击“上传”进行手动同步，或取消对应套餐排除并保存，等待下次巡检继续处理。2FA 恢复、安全存储和有效授权文件等原有资格检查继续生效。

接口字段为账号 `planType`、`autoRepairSkippedReason`、`autoRepairPendingAccountIds`，监控配置 `excludedPlanTypes: string[]`，最近结果 `excludedPlan: number` 与 `autoUploadPaused: number`。未传排除配置字段时保留旧值，显式传 `[]` 清空。未启动的套餐跳过使用 `operationStatus: "skipped"`；授权已保存但自动回传暂停时，授权操作仍为 `succeeded`，由非空排除原因和待处理记录共同表达未完成同步。手动同步确认覆盖同一后端的全部待处理账号后清理暂停记录，旧原因不应继续覆盖当前成功状态。

### 排查边界

页面中的当前套餐是最后保存的快照，不能反推更早入队时使用了什么套餐证据。旧版本没有保存历史入队套餐决策时，只能根据已留存的操作类型、日志和当时配置确认执行路径，不能将“当前显示 Free”直接当作“入队时已知 Free”的证明。排除策略的回归使用合成账号和模拟服务验证，不要求真实账号登录或上传。
