# 推送到 Sub2API 或 CLIProxyAPI（CPA）

在服务配置中分别管理 Sub2API 和 CPA。点击账号行或批量“上传”，支持两种服务时会打开目标选择弹窗，显示本次账号数量和两端配置状态；只有点击“上传到 Sub2API”或“上传到 CPA”才会发送请求。最近使用的目标只作为弹窗预选，取消不上传、不改变勾选账号或偏好。CPA 配置尚未读取或待核实时，先读取核实；未配置时可进入对应配置页。账号页和服务配置页顶部不重复显示目标卡片。

重登授权、重置或设置 2FA 的弹窗仍各自提供 Sub2API / CPA 推送目标选择；勾选成功后自动上传才会在新授权保存成功后推送。默认目标为 Sub2API，偏好保存在当前浏览器。手动上传确认时固定本次账号和目标；上传期间不接受重复提交，回执只更新本轮账号的选择状态。

## 配置与使用

1. 在 CPA 的管理配置中设置管理密钥。填写的是管理接口密钥，不是供客户端调用模型的 API key，也不是配置文件中启动后生成的密钥哈希。若两端不在同一主机，还须在 CPA 中允许来自 toSub2 服务的管理访问。
2. 填写 CPA 服务地址，例如 `http://127.0.0.1:8317` 或 `https://cpa.example.com`。也接受以 `/v0/management` 结尾的管理地址，支持反向代理路径前缀；地址不能包含账号密码、查询参数或片段。Docker 中的 localhost 指容器自身。
3. 按需填写优先级、权重，再保存配置。密钥输入框会清空，同地址留空可沿用已保存密钥；更换地址须重新填写密钥。清空地址并保存可清除配置。
4. 点击账号行或批量“上传”，选择“CPA”，核对账号数量后点击“上传到 CPA”。也可在重登或 2FA 弹窗中选择“推送目标 → CPA”并勾选成功后自动上传。

CPA 的普通 Codex 授权刷新使用固定 OAuth 客户端。当前只推送 ChatGPT/Codex 授权；BPS 和其他 OAuth 客户端的授权会被拒绝。需要 CPA 时可显式选择 ChatGPT 重新授权，不会把 BPS token 改标签后发送。2FA 本地补保存操作不触发推送。号池监控同步到已保存的巡检目标，与手动选择的推送目标独立。

管理地址、版本和不含密钥的凭据引用保存在运行目录的 `cpa-settings.json`。macOS/Windows 使用现有系统保护的凭据库；Linux 在内存中保留密钥，界面会提示重启后需要重新填写。密钥不会返回到配置读取 API、写入浏览器 localStorage、普通任务元数据或公开日志。浏览器仅记住所选目标。已入队操作保留提交时的目标与配置，之后的服务配置编辑或验证码输入不会改变它。

## CPA 优先级与权重

| 配置 | 默认值 | 作用 |
| --- | --- | --- |
| 优先级 | 0 | -2147483648 至 2147483647 的整数。数值越大越优先，在可用账号中选择最高优先级。 |
| 权重 | 1 | 0 至 1000000 的整数。CPA 配置 `routing.strategy: weighted-round-robin` 时，控制同优先级账号的相对分配比例；0 不参与加权轮询，不等同于禁用账号。 |

例如，同优先级的两个账号分别设置权重 3 和 1，在加权轮询下按约 3:1 分配；可用性、冷却和会话亲和等规则仍会影响实际选择。使用 CPA 默认的 `round-robin` 策略时，权重不会改变普通轮询的分配。

这两个值随下一次手动或自动推送写入授权文件，批量推送使用同一组配置。只保存本地配置不会修改已经推送的账号，也不会改动 CPA 的全局路由策略。旧版配置未填写时按 0 / 1 处理；已入队任务继续使用入队时的数值。Sub2API 的优先级、并发数、负载因子等仍在其独立配置页设置，与 CPA 权重互不混用。

## CPA 异常重登与套餐排除

所有巡检设置统一放在“号池监控 → 巡检配置”表单中。在“巡检对象”下拉框选择 Sub2API 或 CPA，下方共用一套“自动巡检与重登”、巡检间隔、重登冷却及“自动重登排除套餐”。点击“保存巡检规则”后，只巡检所选服务；切换对象保留当前规则。巡检间隔可设为 1–1440 分钟，重登冷却可设为 0–1440 分钟，0 表示不限制冷却；默认均为 5 分钟。连接状态及“服务配置”入口位于下拉框旁，Sub2API / CPA 服务配置页保留各自的连接与推送参数，保存连接不会改动巡检规则。

页面通过“巡检配置 / 巡检记录”两个选项卡切换视图，支持键盘方向键、Home 和 End。切换视图保留未保存的规则，不触发保存、查询或检查。“巡检记录”使用一张卡片集中展示“最近巡检结果”和“账号查询概览”，保留各自统计、状态和异常提示。

巡检目标和规则一起保存在服务端，刷新或重启后恢复；重登／2FA 弹窗中的推送目标仍独立选择。“服务配置”跳到当前所选服务的连接设置。未保存的目标选择不会改变后台运行目标，状态和最近统计显示已保存目标的结果。页面可见时每 5 秒只读更新状态，保留未保存草稿；离页时提示处理草稿。保存或检查结果未知时必须显式“读取并核实”，被动轮询不会解除此保护。CPA 的“已排队自动重登”仅表示入队，重登和上传结果需到账号列表查看。

共享策略通过 `GET/POST /api/pool-monitor` 读取和保存，提交配置版本、巡检目标、开关、套餐、间隔和冷却；通过 `POST /api/pool-monitor/check` 检查已保存目标。服务端保留两端已有连接、管理密钥和推送参数。旧配置首次启动时迁移到单份共享规则，未选中目标的自动巡检和待执行自动修复会被停用。

巡检通过 `GET /v0/management/auth-files` 读取状态，只处理本工具生成且与本地已保存授权身份一致的 Codex 文件。明确的授权失效（例如 `invalid_grant`、refresh token 撤销或过期）才可触发自动重登；停用、运行时记录、限流、额度不足、封禁、网络和服务器故障不会触发。CPA 列表缺少明确状态时不猜测授权失效，也不自动接管其他工具上传的文件。

自动重登还要求上次完整授权为全自动完成、所需密码／收码 API／2FA 密钥仍可读取，且没有其他运行中任务、恢复待核实或上传暂停。重登后新授权先保存，再更新同名 CPA 文件；若账号 workspace 身份变化，保留新授权并暂停上传，避免创建错误文件。

自动上传前再次读取 CPA 文件状态和套餐。如果重登期间原文件已停用、删除、自行恢复或身份变化，则保留本地新授权并暂停回传；状态读取失败时同样不覆盖。手动上传仍按用户选择直接更新授权文件。

“自动重登排除套餐”允许多选。本地、CPA 和新授权中的已知套餐任一命中即阻止相应的自动操作；未知不等于 Free。入队、执行登录前和上传前分别检查策略。规则不影响用户明确选择的手动重登或手动上传。重登／2FA 弹窗中的目标选择只决定该次操作。

更换 CPA 地址、密钥或推送参数后，旧的自动任务停止使用旧配置；关闭监控或增加套餐排除也会阻止尚未执行的登录／上传。已经完成的授权始终保留。上传失败、回执未知或流程中断后自动回传暂停，不会为重试上传而再次登录，也不会被另一目标的巡检接管；请核实 CPA 文件和本地授权后显式手动操作。配置保存持久化未确认时，同样暂停自动修复并提示重新保存。

## 上传文件及结果

集成依据 [CLIProxyAPI commit 1aaf56bc6a0fc6fce19049ba7ae8554c882304a6](https://github.com/router-for-me/CLIProxyAPI/tree/1aaf56bc6a0fc6fce19049ba7ae8554c882304a6) 的管理接口与 Codex 存储格式：

- 使用 `POST /v0/management/auth-files?name=...`、Bearer 管理密钥和 JSON 正文。
- 将本地已提交的授权转换为 `type: codex` 的扁平文件，包含 access token、refresh token、账号 ID、邮箱及已有的 ID token／到期信息；不包含密码、2FA 或 Cookie。
- 文件名为 `tosub2-codex-<邮箱与账号ID的SHA256>.json`。重复推送相同邮箱和账号 ID 会替换本工具创建的同名文件；不会查找、合并或删除其他来源的文件，也不会保留该同名文件上手工添加的 CPA 专有字段。不同 workspace/account ID 使用不同文件名。
- 上传成功表示 CPA 已接收并注册授权文件，不代表已验证模型调用权限。不会为了推送执行登录、token 刷新或额外模型请求；已启用上传前质量门禁时仍按该策略检查。

批量推送先验证整批授权兼容性和质量门禁，再逐条上传；每条发送前复核当前策略与授权。失败后停止后续账号，返回已成功、失败、未知和未执行项。连接中断、5xx 或无法确认的回执不会自动重试；请先在 CPA 的授权文件列表核实。收到 HTTP 200 且明确 `status: ok` 才计为确认成功，远端错误正文不会公开。

配置保存失败会区分“旧配置保留”和“文件已替换但持久化未确认”。结果未知时，页面要求显式读取当前配置核对，不自动重发保存请求。有效读取中的凭据错误仍允许重新填写密钥修复。
