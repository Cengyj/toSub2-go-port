## 已确认问题与修复

1. **服务关闭过早返回。** 原 Close 只等待后台循环，没有等待直接 Update／Sweep 持有的 gate，可能返回成功后仍在写策略或清理。三组先红后绿回归覆盖未启动和已启动后台的 Update，以及直接 Sweep。现在按调用方 context 预算等待 gate，超时返回错误。
2. **缺损策略被默认值补成有效。** 原 JSON 解码前预填 schema/revision，使缺失或 null 字段通过校验。现在仅在文件不存在时使用默认值；已有文件从零值解码并校验。前端同样拒绝 revision 0，合法初始 revision 1 保持。
3. **会话隔离不完整。** token／功能变化时旧设置锁、authority、草稿和回执可能残留。现在使用代际对象，覆盖 A→B→A 和关闭重开，取消旧请求并隔离旧回调与锁。
4. **未知操作核实期间可写策略。** saveSettings 现在遵守 verify 门禁，输入与保存同时禁用。设置页新增“核实回收站状态”只读入口：切页停止列表轮询后，仍能在当前页核实并解除门禁，不重放操作。
5. **查找和操作范围不清。** 新增邮箱／回收 ID／历史 ID 搜索、状态筛选、排序、20 条分页。“选择本页”仅作用于当前页，跨页选择保留并显示隐藏数量；确认框也明确包含这些账号。恢复资格不足时不静默只恢复一部分。
6. **确认等待期间目标变化。** 提交前用最新邮箱、移入时间、状态、历史组身份及可恢复标志重校验。目标变化、会话变化和页面卸载时不再提交旧确认；双击仍只提交一次。策略页卸载后也不会继续保存或写 UI 状态。
7. **窄屏横滚、日志撑开列表与焦点丢失。** 使用独立详情弹窗复用原 JobLogs，移动端改为单套 DOM 的卡片布局。记录消失时明确失效；焦点从失效日志控件移到关闭按钮，关闭后再回列表标题，避免被尚未卸载的弹窗焦点约束拉回。

职责分别归属：列表与确认在 trash-records.jsx，详情在 trash-details.jsx，策略表单在 account-trash.jsx，纯展示与选择规则在 lib/accountTrash.js，请求生命周期在 hooks/accountTrash.js，本地策略与调度在 internal/recyclebin/service.go。未新增通用框架或额外业务接口。
