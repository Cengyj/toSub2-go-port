# 账号用量与状态查询

更新日期：2026-10-31。本页说明新增代码的使用与运行边界；实际部署版本、全量回归和真实页面验收以对应的 [部署记录](local-deployment.md) 为准，不把实现或交叉编译结果当作真实账号、所有上游端点或其他操作系统的验收。

## 构建版本与安全调整

当前 `go.mod` 的最低源码版本为 **Go 1.26.0**，生产工具链固定为 **Go 1.27.3**；CI 和 Docker 的生产构建使用相同工具链。最低版本测试是源码兼容性检查，不代表生产应改用较旧工具链。前端仍使用 Go esbuild API 与受控 vendor，认证动态 JavaScript 仍由内嵌 Sobek 执行，无新增外部语言或浏览器运行时。

本轮针对安全检查发现的可达问题做了定向调整：`GO-2026-6860` 对应的 `golang.org/x/net` 升至 `v0.62.0`，`GO-2026-6809` 对应的生产 Go 工具链升至 `1.27.3`；随依赖约束同步锁定 `x/crypto v0.58.0`、`x/sys v0.49.0`、`x/text v0.43.0`。版本以 `go.mod` / `go.sum` 为准，不通过降回旧依赖或跳过测试维持原最低版本。

漏洞检查工具固定为 `govulncheck@v1.9.0`，可在漏洞数据库可达时用 `GOTOOLCHAIN=go1.27.3 TOSUB2_VERIFY_VULN=1 ./scripts/verify.sh` 执行完整验证并附加扫描。这里只记录已落地的版本调整；全量回归、漏洞复扫和部署验收是否通过，需以本轮实际结果记录为准。

## 启用与使用

在 **服务配置 → 账号用量与状态查询** 中勾选“启用账号查询”，选择更新方式并保存。总开关默认关闭；默认更新方式为自动，间隔为 15 分钟，额度重置券明细默认关闭。只有总开关启用并成功保存后，后台才接受手动查询或安排自动采集。

- 自动间隔接受 **1–1440 的整数分钟**。它控制 Go 服务访问上游的频率，不是网页刷新频率。冷却、请求预算、账号操作和队列可能使实际查询晚于该时间。
- “仅手动查询”关闭定时采集；账号行的用量摘要、更多操作中的“用量与状态”和批量查询仍可使用。
- 启用并保存后，账号管理页的状态栏显示“账号状态与用量”和“刷新全部账号用量”。该入口由服务端读取完整账号库存，不受当前分页、筛选或勾选范围影响；关闭功能后隐藏入口。列表区标题为“账号用量与操作”，工具栏直接显示“刷新所选用量”，只处理勾选账号，无须打开“更多”菜单；未启用查询或未选中账号时该按钮不可用。
- 全量查询沿用手动查询的安全门禁、冷却和重复提交合并；自动查询排除名单不禁止手动查询。提交时显示“正在提交查询…”，并禁用重复操作；回执区分受理、合并和跳过，不宣称查询已完成。队列与执行中查询合计仍最多 **1000 个**，超出容量的账号明确列入“队列已满”跳过项，可待队列释放后再次提交，不会静默截断或自动无限追加。
- 在账号详情中可取消“此账号参加自动查询”。这个排除项只影响自动查询，手动查询仍受总开关、冷却及账号安全条件约束。
- “包含额度重置券明细”只读取可用数量与到期时间，不使用或消费重置券。
- “保存查询配置”作用于服务端；刷新网页、关闭浏览器或换浏览器仍使用同一配置。**清除网页设置不会停止后台采集，也不会清除服务端查询设置或缓存。**
- 未保存的表单是当前页面的草稿；点击“放弃更改”恢复最近读取的配置。“重新读取配置（放弃草稿）”会舍弃当前草稿。

账号表格在邮箱右侧设有独立的“用量 / 已用比例”列，CSS 基础宽度为 **220px**（实际宽度随表格分配），展示最近缓存中的最多两个主额度窗口。每个窗口依次显示窗口名称、上游原始已用比例、全宽进度条和预计重置时间。窗口按上游实际时长标注，例如 5h 和 7d；进度条表示已用比例，不是任务完成进度，也不是剩余比例。点击这一列可打开“用量与状态”详情；额外窗口在详情中查看。

列表不展开具体错误原因，也不单列“部分更新”等过程提示。重置时间行右侧以红色短标识显示 `HTTP 401` 等状态；没有 HTTP 状态时只显示“查询异常”。有明确额度用尽证据时显示“额度已用尽”，历史或预计重置已过时显示“上次已用尽”。每个账号只显示一次短状态，HTTP 错误优先；悬停短标识仅说明来源与状态，完整原因留在详情。没有额度窗口的账号仍显示“重置时间未知”和可用错误标识。

点击整个用量单元格打开同一详情窗口，按 Codex 额度、BPS 模型权限、账号与订阅、额度重置券或查询任务分组查看错误。来源、HTTP 和原因直接显示；内部错误码、安全诊断、记录类型、冷却及建议在对应诊断区查看。没有返回 HTTP 状态或重试时间时明确提示缺失，不补成成功或可立即重试。历史成功用量继续保留。

每个窗口显示已用百分比和预计重置时间。真实 0% 保留为零；缺少数值显示“未知”和斜纹占位，不画成零额度。条宽限制在 0–100%，文字仍保留上游实际数值。75% / 90% 的颜色仅作为视觉提示，不改变授权、上传或查询资格。历史额度弱化显示并标注；经过预计重置时刻后显示“待确认”，不会自行归零。仅取得 BPS 权限时显示权限与“额度数值未知”，不将许可转换为百分比。

列底部按实际展示来源标注“额度观察”“权限观察”或“订阅观察”，避免把某个来源的成功时间当作全部数据更新时间。紧凑显示可省略年份；悬停 `title` 保留完整本地日期时间，`time` 元素的 `dateTime` 保留来源原时间。重置倒计时也保留完整预计重置时间提示。

详情按紧凑标题与授权方式、查询状态、统一操作栏、来源错误、额度主卡、辅助信息卡和巡检来源排列。来源错误位于观察数据之前，HTTP 与原因直接可见；“诊断与恢复”使用可键盘展开的原生折叠区。Codex 额度占据整行主区域，credits 与重置券、BPS 权限、账号与订阅在下方响应式排列，各自保留来源说明和观察时间。ChatGPT 授权且没有 BPS 观察时不展示空 BPS 卡片；BPS 授权或已有 BPS 观察时仍显示对应权限区。读取、查询操作和配置错误分别提示，避免互相覆盖。布局不会把 credits 当作 BPS 余额，也不会将权限可读解释为额度查询成功。

点击“立即查询”、全量查询或所选账号查询才提交手动采集。提交回执分别列出已受理、已合并在途查询和已跳过的账号；**HTTP 202 / 已受理不代表查询成功或完成**。排队、执行中、部分更新、失败及保存未确认在详情及查询概览保留各自语义，列表只显示紧凑的数值、短标识和来源观察时间。查询概览根据实际执行数和排队数显示活动，不把后台服务存活误当成“正在查询”。打开进度条详情仍只读取本地缓存，不新增逐行上游请求或计时器。

同一任务 ID 的重复提交合并到已有查询，不再创建第二份工作。多个本地记录属于同一邮箱时，调度器仍按规范化邮箱协调，避免与该邮箱的登录、重登、刷新、2FA、删除或恢复并发。其他账号可继续执行。

## 后台采集与网页读取

Go 服务拥有采集队列、间隔、冷却和查询结果。浏览器只通过本地 API 读取缓存：账号摘要、详情和监控概览目前使用约 5 秒的读取周期，查询配置约 30 秒读取一次；可见页面、网络状态和已有请求会影响读取时机。打开详情、刷新页面、轮询或多开标签页不会直接访问 OpenAI 信息接口。

用量列和详情布局更新不改变后台真实采集频率、已保存偏好、请求与重试规则。每个账号行只展示传入的缓存数据，不创建独立轮询或额外上游请求。

后台当前最多同时执行两个账号查询，带有启动间隔；新账号或身份变化后的自动查询分散启动。单个查询设置 30 秒总预算，子来源还有更短预算。临时网络故障只对符合条件的只读 GET 有界重试；权限拒绝、业务拒绝、HTML/挑战页和重定向不会触发登录或被统一当作网络错误重复尝试。

查询服务与账号任务、Sub2 自动修复巡检分别统计。账号查询的“已完成”只表示本轮取得了有效的信息观察；不能据此认定授权上传、模型生成或远端修复完成。

### 取消、关闭和重启

- **关闭详情窗口或浏览器**：停止该页面的读取，已受理的后台查询继续执行。
- **取消查询**：取消该账号的排队或执行中查询；保留此前有效观察。取消请求确认后，等待状态变为已取消或中断。
- **关闭总开关并保存**：停止接受手动查询，取消排队与执行中查询，不再安排自动查询；已有缓存仍可查看。
- **停止 Go 服务**：取消查询并等待网络与租约释放；不会为清理资源而删除账号、授权或缓存。
- **重新启动**：读取有效的持久设置。上次未完成查询显示中断；历史结果带有过期/历史提示。仅在已保存设置允许时恢复自动安排，不把上次的排队回执认定为完成。

登录、刷新、2FA、删除和恢复具有优先级。它们可取消正在进行的只读查询，但同一邮箱的新认证网络工作会等待查询释放传输资源。查询结果在保存和发布前再次核验账号、授权文件、代理和配置状态，已取消或被替代的结果不会成为新观察。

## 各来源的含义

| 来源 | 能说明什么 | 不能据此推断什么 |
| --- | --- | --- |
| Codex 额度 | 上游实际报告的使用窗口、已用百分比、允许状态、限制状态和预计重置时间 | 所有模型都能生成、OAuth 仍永久有效、BPS 余额或 Sub2 健康 |
| Codex credits | 上游报告的 credits 数值或明确的无限状态 | 美元余额、Token 数、BPS 独立余额 |
| 额度重置券 | 已启用该选项且查询成功时的数量及到期时间 | 已消费券、已执行额度重置 |
| BPS 模型权限 | BPS 主授权的总体访问许可、模型可见/可用/受限状态和已报告能力 | 模型生成实测通过、BPS 独立剩余额度、账号整体被封禁 |
| 账号与订阅 | 与当前账号/workspace 和套餐范围核对后的订阅元数据及可用期限 | access token 的有效期、额度窗口的重置时间 |
| Sub2 远端状态 | 本轮缺少普通上传的持久化远端绑定收据，明确显示未知 | 已有本地授权、可查询 Codex 或 BPS 就表示 Sub2 正常 |

这些来源独立成功或失败。BPS 权限可读而 Codex 额度被拒绝时，应显示“部分更新”及具体来源错误，不把 BPS 可访问换算为额度。未返回字段、明确 `null` 和合法的 `0` 不混淆：缺少数值显示未知，真实零用量或零余额保留为零。

“额度已用尽”不等于授权失效；“权限接口受限”不等于整个账号封禁。当前实现没有发起模型生成来测试可用性。BPS 没有可信的独立数值余额来源时，保持未知。

当前普通上传仅返回本次聚合结果，尚未持久保存“具体 Sub2 后端 + 明确远端账号 ID + 本地任务”的完整绑定。自动修复的待回传 ID 与后端是恢复意图，成功后会清理，也不是实时状态收据。因此本轮不按邮箱、返回数组顺序或整轮巡检计数猜测某个本地账号的 Sub2 状态，不为填满这个字段触发上传或改变远端调度。

### 历史结果和时间

每个来源保留自己的 `observedAt`。新查询失败或部分失败时，旧的成功观察可以继续展示，但仍使用原来的时间和历史提示；本轮尝试的开始/结束时间不是所有来源的数据更新时间。重置券明细也保留独立观察时间：例如关闭重置券查询后继续保留的旧明细，会按该来源的时间标为历史，不因 Codex 额度或其他来源刚更新而变成新观察。

“预计已重置，待更新确认”只表示观察中给出的时间已经经过，不会在本地自行把用量归零。历史数据或预计重置已过的观察仍报告额度用尽时，提示为“上次查询已用尽”，不宣称当前仍然用尽。长期未成功更新的缓存会标为历史；服务重启读回的缓存也先视为历史。配置间隔改变不会把旧数据变新。

服务端将观察、尝试、冷却和下次检查时间保存为 UTC 的 RFC3339 时间。网页按浏览器所在时区显示。请求使用的 OpenAI 时区是另一项配置，沿用服务配置中的值，空值默认 **America/Los_Angeles**；它不改变 UTC 存储规则，也不改变浏览器时区。

### 到期时间优先级

账号有效期继续遵循：**有效的手动到期时间 → 已核对身份的订阅到期时间 → 未知**。查询不会覆盖手动有效期，不会把 token 到期或额度重置日期当作订阅到期。

只有当前任务、授权方式和上游账号/workspace 范围匹配，且订阅接口明确报告该字段时，查询观察才用于期限展示。上游明确报告无日期时不复活旧订阅日期；接口省略日期或身份/套餐范围无法核实则不编造期限。查询数据保存在独立缓存中，不因此改写账号的手动日期或授权文件。

## 授权、代理与安全边界

查询只使用已提交的主 OAuth 导出 `sub2api-import-oauth.json`，保留该账号保存的 ChatGPT 或 BPS 身份，不读取浏览器登录偏好来切换方式。文件必须属于当前任务并满足身份、大小、路径和私有权限检查；未完成的 token 轮换恢复文件会阻止查询使用旧结果。

- 不自动登录，不调用 token 刷新，不执行 2FA 变更、退出设备、上传、模型生成或重置券消费。
- access token 已知过期时，在网络查询前提示“刷新授权”，等待用户通过原有账号流程处理；未知到期不假设已经过期，也不假设永久有效。
- 身份不匹配或已知过期的授权不会按固定间隔反复尝试；当前授权来源变化后重新评估。
- 账号已保存代理优先；受保护代理读取失败会明确失败，不静默改用直连。显式直连与“没有账号覆盖、使用全局代理”分别处理。
- 未保存明确出口的代理池或仍含动态占位符的代理，不为查询随机生成新身份。TLS 身份不可用也不自动换成别的配置。
- 查询使用受控的只读信息端点与独立传输资源，不使用未完成登录 checkpoint 的 Cookie、OAuth state 或挑战流程来补救查询失败。
- 返回浏览器和写入查询缓存的都是归一化元数据，不包含 access/refresh/id token、密码、2FA 密钥、代理凭据或 Sub2 管理密钥。

原有授权、2FA 恢复、上传去重、套餐排除和自动修复流程仍各自执行原有规则。仅查询信息不会修改 Sub2 账号状态、清除错误或恢复远端调度。

## 故障与恢复

### 阅读查询错误

先从用量列进入“查看错误详情”，核对失败来源、HTTP 状态和 `code`，再看该来源的观察时间与冷却。详情中的“来源历史错误记录”可能来自前次查询；它不表示本轮又发送了请求或再次失败。冷却已过也不表示接口已恢复，账号资格、总开关与其他安全条件仍需满足。打开错误详情只读本地缓存，不触发上游查询、刷新授权或重登。

后续查询可以附带三类安全诊断：`upstreamCode` 是上游结构化错误码，`upstreamType` 是上游结构化错误类型，两者只保留程序认可的协议常量白名单；`transportReason` 是 DNS、TLS、证书、连接或超时等封闭网络分类。未知自由文本、上游原始 message、响应正文、Cookie、账号/凭据、带参数 URL 和 request ID 均不透传或保存到这些字段。字段为空可能表示上游没有提供、内容不在白名单、响应无效或该缓存来自旧版本，不代表没有错误。

旧缓存只能展示当时已保存的 HTTP 状态、错误码和固定说明；没有保存的原始响应无法通过升级还原，也不会为了补充诊断主动重新查询真实账号。新增字段只有在之后按已保存自动计划自然查询，或用户明确点击手动查询且满足冷却及资格条件后，才可能补充。失败仍保留当前授权身份下可用的历史成功观察及其原观察时间；查询功能不会因为错误自动刷新 token、重新授权、上传或修复远端账号。

| 提示/情况 | 含义与处理 |
| --- | --- |
| 尚无已保存授权 | 没有可供查询的主授权；查询不会替代首次授权。使用原有授权入口。 |
| 当前 access token 已过期 | 已保存的有效期已过；使用原有刷新/重新授权操作，完成后再查询。不能把旧授权文件删掉作为修复。 |
| 身份不一致 | 保存方式、邮箱、workspace 或客户端身份不匹配；先核对当前授权，查询不猜测或切换身份。 |
| 账号操作进行中 / 恢复待完成 | 查询暂缓；先完成或取消当前流程。已有 token 轮换或 2FA 恢复记录继续使用原恢复入口。 |
| 代理不可读取 / 需明确代理出口 | 核对账号代理和凭据存储可用性；不会自动绕过代理。 |
| HTTP 401 / `authorization_rejected` | 当前来源拒绝了本次查询使用的已保存授权。核对授权方式及来源错误；仅凭 401 不能断言整个账号被封禁，也不能确定就是 token 到期。查询不会清除历史授权或自动重登/刷新。 |
| HTTP 402 / `upstream_error` | 查询接口返回 402，本轮未取得该来源数据。结合可用的安全上游错误码/类型核对访问条件；仅凭状态码不能确认欠费、套餐过期或整个账号失效。保留原有拒绝和冷却规则，不套用临时网络重试。 |
| 权限拒绝 / 不支持该授权 / 挑战页 | 记录来源级错误与冷却，其他可用来源独立处理。查询不会启动浏览器或认证 worker 解决挑战。 |
| 限流 / 网络错误 / 超时 | 展示具体来源的失败和下次允许查询时间。失败会有界退避，尊重较晚的 `Retry-After`；反复手动点击不会绕过冷却。 |
| 部分更新 | 至少一项取得新观察，另一些失败、受限或仍在冷却。逐项查看来源、错误和观察时间。 |
| 查询已完成但未可靠保存 | 当前内存可能已有结果，磁盘写入未确认；检查数据目录、权限和磁盘后再查询。不能承诺重启后仍有该结果。 |
| 配置已被其他页面修改 | 版本冲突；重新读取配置，核对后再次保存。不要用旧标签页覆盖新设置。 |
| 保存结果或持久性未知 | 可能在文件替换后发生持久化确认失败，或浏览器没有收到确认。先重新读取，再明确保存；“重新读取”本身不等于已修复持久性。 |
| 服务暂不可读 / 离线 | 页面保留最近读取的缓存并提示失败；网页无法确认后台当前进度。恢复连接后重新读取。 |
| 账号已删除，但查询缓存尚未完全清理 | 账号删除已经完成，不会回滚；部分查询元数据可能仍在磁盘。检查数据目录和权限后重启或在后续删除时重试清理，无需再次删除同一账号。 |
| Sub2 远端状态未知 | 缺少可验证的远端绑定或可靠观察，并非远端健康或失败。不要通过重新授权/上传来“测试”这个字段。 |

关闭总开关的保存失败时，当前进程仍尽量停止采集并提示配置未可靠保存。文件替换已经发生但目录同步结果未知时，服务读回可见版本用于协调 revision，并在当前进程关闭查询；**重启后的开关值仍需要核对并明确保存**。不要只看到已停止就认为关闭设置已经持久化。

来源级错误分别退避，不让一个暂时不支持的接口拖累其他来源。已知不支持的授权类型使用较长冷却；权限/身份/响应结构问题也不会按页面轮询频率重复请求。全局失败、跳过、取消和部分更新分别展示，不计作同一种成功。

## 设置与缓存文件

查询数据位于实际运行配置的 `OutputRoot` 下；不要把项目目录里的同名测试目录当成运行数据。

```text
<OutputRoot>/
  account-insights/
    settings.json
    <本地任务ID的SHA-256>.json
  <job-id>/
    sub2api-import-oauth.json
    ...原有账号与恢复文件
```

- `settings.json`：schema version、revision、总开关、自动/手动模式、分钟间隔、重置券选项和自动查询排除任务 ID。
- 哈希命名文件：当前授权来源版本下的最近归一化观察、尝试状态、时间和来源冷却。哈希只是文件命名，不是加密，也不证明远端身份。
- 查询设置与快照采用私有原子写入。POSIX 目录/文件使用 `0700` / `0600`；Windows 由现有私有文件模块建立并验证当前用户受限 ACL。是否在具体平台完整验收须另看验证记录。
- 读入检查普通文件、身份与私有权限，拒绝符号链接、超限或无效 JSON。设置不可安全读取时关闭功能并保留原文件；无效快照不冒充可用观察。
- 查询缓存不是凭据备份，也不含可恢复登录所需的全部材料。即使不含 token，账号标识、套餐和使用观察仍应作为私有数据管理。不要把运行目录、真实日志或缓存加入 Git。
- 成功删除账号后，服务取消其查询、移除内存摘要，并清理能验证为该已删除任务的 schema 1 哈希快照。清理与查询提交串行化，已取消查询的迟到响应不能重建缓存；活动传输资源仍由原查询在结束时释放。
- 清理只删除私有普通文件，且其中的任务 ID 必须与哈希文件名一致。当前账号、查询设置、未知 schema、无效 JSON、名称不匹配文件、目录和符号链接均保留，不递归删除整个缓存目录。哈希不是安全擦除保证，独立备份也不受该操作影响。
- 删除已完成但缓存无法清理时，API 和页面明确说明“部分完成”，不伪装回滚或完全成功。后续账号删除与服务启动会再次清理可验证的遗留快照；启动清理失败只显示安全警告，不阻止服务启动。若需移除未知历史文件，请停服务后按下述重置/卸载范围确认处理，不能把页面隐藏当成磁盘数据已擦除。

## 备份、升级、回退与卸载

### 备份与升级

1. 先保存需要保留的查询配置。计划维护时关闭查询并等待查询的排队/执行中计数归零，同时按原部署流程确认账号任务、认证 worker 和巡检没有未结束的写入。
2. 停止服务后备份实际运行目录和原有凭据存储；将 `account-insights/` 一并纳入私有备份。备份应覆盖原有账号、授权与 checkpoint，不能只复制查询缓存。不要打印真实文件内容作校验。
3. 沿用 [Go 构建、运行与升级说明](../go-deployment.md)，让二进制与嵌入前端资源来自同一构建。新功能不引入 Node、Python、Chromium 或独立登录运行时。
4. 使用原 OutputRoot、配置和凭据 namespace 启动。核对健康、实际二进制和前端资源，重新读取查询配置；首次启用仍由用户明确决定。

### 回退或只重置查询功能

回退前停止服务并确认任务已结束。仅替换为已知可用的旧二进制，保留账号、凭据、授权文件和恢复记录；不要用更早的账号元数据覆盖之后完成的 token 轮换或安全操作。本功能不要求迁移原账号或授权格式。

如果只要重置查询设置与缓存，先停服务，将整个 `<OutputRoot>/account-insights/` 移至权限受限的备份位置，再启动当前版本：查询会回到默认关闭且暂无缓存。不要移动或删除相邻 `<job-id>/` 目录。仅关闭功能时无须删除任何文件。恢复查询备份也应停服务，核对 schema 与原任务/授权是否仍匹配，再重新确认开关；旧缓存会被视为历史，不是新观察。

### 停用与彻底卸载

普通 `stop` 保留查询设置、缓存、账号和凭据。若仅移除本功能的数据，在服务停止后删除已经确认不再需要的 `account-insights/` 备份/目录；网页清理不能代替这一步。

完整卸载沿用 [本地部署与清理范围](../local-macos.md) 和 [Go 部署说明](../go-deployment.md)。已有本地实例脚本的 `clean --yes` 会删除它所管理的运行目录及专属凭据；当 OutputRoot 位于该目录内时，查询缓存也一并删除。自定义外部输出目录、外部备份和其他独立安装不应假设都在该脚本的清理范围内，应逐项确认。卸载是有意的数据删除，不能作为查询故障排查步骤。

## API 与实现定位

所有接口继续经过控制台 token、Host、Origin 和 Fetch Metadata 边界，响应不缓存。下表用于开发与排障，不需要在浏览器以外复制真实控制台 token。

| 接口 | 语义 |
| --- | --- |
| `GET /api/account-insights/settings` | 读取服务端配置，不查询上游。 |
| `PUT /api/account-insights/settings` | 携带当前 revision 保存设置；冲突为 409，校验失败为 400，持久化失败为 503 并说明 failed/unknown。 |
| `GET /api/account-insights?ids=...` | 一次最多读取 100 个任务缓存，不存在的 ID 不返回。 |
| `GET /api/account-insights/<job-id>` | 读取一个任务缓存；不存在时 404。 |
| `GET /api/account-insights/status` | 查询服务状态、队列、最近结果分类计数和下次检查，不查询上游。 |
| `POST /api/account-insights/refresh` | 使用 `{"ids":["synthetic-account"]}` 提交 1–1000 个任务 ID，或 `{"all":true}` 查询完整库存。全量请求不能同时提供 `ids`，包括空数组或 null。202 仅表示返回受理/合并/跳过回执；关闭或未运行时不受理。 |
| `POST /api/account-insights/queries/<job-id>/cancel` | 取消该任务的查询；路径使用任务 ID，不是批量回执中的 queryId。 |

主要代码为 `internal/accountinsight/`（调度、缓存与投影）、`internal/application/account_insights.go`（已保存授权读取）、`internal/jobs/account_query.go`（同账号租约）、`internal/protocol/account_insights*` / `account_subscription.go` / `bps_access.go`（只读协议），以及 `web/src/hooks/accountInsights.js`、`web/src/components/account-insights.jsx`（本地缓存读取与交互）。表格摘要在 `web/src/components/account-usage.jsx`，详情分区在 `web/src/components/account-insight-details.jsx`；两处共用纯展示 `UsageMeter`，保持窗口、原始比例、进度条和重置语义一致，组件自身不请求数据或安排任务。

验证应使用合成账号、模拟传输和独立临时目录。定向入口包括 `TestAccountQuery*`、`TestAccountInsightGrant*`、`TestAccountInsightsAPI*`、`TestPruneDeleted*`、`TestAccountInsightsAccountDelete*` 与 `internal/accountinsight` / `internal/protocol` 的查询回归；交付前还需执行项目全量 test、race、vet、Go 前端及纯 Go 生产构建、平台验证和本地部署核验。本页不代替这些步骤的实际结果记录，也不要求真实账号登录、2FA 或上传作为测试。
