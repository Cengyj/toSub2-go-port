## 实施中修复的具体问题

- 配置保存不确定时读回可见 revision，在当前进程停止采集；HTTP 503 区分 failed/unknown，前端要求核对后明确保存。
- 调整更新间隔后重排到期时间；各来源分别退避，usage 权限不足不拖慢健康 BPS 查询；尊重 Retry-After。
- 取消不会在下一 tick 立即自动重排；整体预算超时显示失败而非用户取消。
- 保存前后验证租约、授权代次和取消上下文，拒绝迟到结果。历史成功数据不会被一次失败清空。
- 额度重置券、订阅日期保留独立观察时间；日期显式 null 与本轮缺失/失败分开处理。
- 超过队列容量时按最早到期稳定排序，1001 个合成账号回归避免后段账号长期饥饿。
- API 分页摘要一次获取账号清单；总览不再统计已删除或旧授权快照。
- GUI 实测修复“无观察却显示已获取”和“配置未知读回后丢失待核实提示”。
