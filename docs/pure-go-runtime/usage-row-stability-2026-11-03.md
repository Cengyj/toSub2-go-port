# 刷新状态行高稳定性（2026-11-03）

## 问题与本轮范围

基于当前 `main` 工作区继续修改，保留全部未提交成果。用户指出刷新状态会改变账号行高度。已复现三个原因：有数值时插入独立状态行；无数值时插入额外说明；`lastAttempt.startedAt` 改变历史判断后追加独立历史标签。它们共同推移后续账号，影响定位正在刷新的行。

本轮仅调整用量展示和回归保护，不改变服务端采集、账号互斥、查询资格、冷却、取消、授权、上传或 BPS 模型规则；没有数据迁移、依赖升级或新增运行时。

## 已实施设计

| 场景 | 展示位置与内容 | 稳定性措施 |
| --- | --- | --- |
| 有窗口且有数值 | 首个窗口标题内“排队中／刷新中” | 50px 单行状态槽空闲时仍保留位置，额度条和原数值不变 |
| 有窗口但数值全部未知 | 同一标题槽内“排队中／查询中” | 保留原未知窗口，不新增空状态块或虚构进度 |
| 无窗口、只有 BPS 权限或无数据 | 原图标切换时钟／旋转图标；原副标题改为“等待查询／正在查询” | 第一行继续展示权限，始终维持两行 |
| 历史额度或权限 | 观察时间行第一标签原位改为“历史额度／历史权限” | 不另建历史标签行；日期缺失显示“未知” |
| 长名称、长精度数值 | 紧凑列单行省略，完整内容在 title、无障碍描述及详情中保留 | 不四舍五入，不改变原值；数值列可收缩，避免挤出用量列 |

来源与观察日期取同一个对象：usage 优先，其次 BPS，再 subscription。usage 缺失日期时不会借用新 BPS 或订阅时间。保持原订阅专用历史标记边界，本轮没有扩展订阅状态规则。

没有给整个表格固定行高，没有把用量条当成查询完成百分比。真正的新数据改变窗口数量或文字内容时，行高仍可自然调整；本轮保证的是同一份观察数据在查询阶段切换时不跳动。

实现：`web/src/components/account-usage.jsx`、`account-usage.css`。删除已无 DOM 使用点的 `.usage-query-state`、`.usage-query-note`、`.is-query-placeholder` 和独立 `.usage-history-label` 样式；没有删除业务逻辑、数据或测试。

## 回归与真实浏览器证据

测试先在旧实现明确失败，再随实现通过。新增稳定结构矩阵覆盖 11 类数据 × 8 个阶段（88 组）；另有 6 类来源缺日期 × 4 个阶段（24 组），包含 usage 无日期但 BPS 有日期、BPS 无日期但订阅有日期，防止串用观察时间。34 个 `TestFrontendUsage*` 顶层测试均通过 race。既有数值、0／未知、HTTP 错误、权限、旧观察、实际 flight 状态优先、终态和键盘入口保护保留。测试工具仅增加新纯组件 `UsageQuerySlot` 的展开，不弱化断言。

- 152px 用量内容区中，长精度数值与状态槽不重叠，行内容宽度与 scrollWidth 同为 152px；完整原值保留。
- 查询中 Enter 打开详情，取消合成查询后保留原 0%／61.25% 与观察时间；Escape 关闭后焦点回原用量按钮，行高不变。
- 双击“刷新所选用量”只产生 1 次合成刷新 POST，排队期间按钮禁用；批量按钮旁没有新增可见计数。
- 浏览器 error/warn 日志为空。
