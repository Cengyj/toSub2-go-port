# Go 版重置 2FA

## 使用方式

- 尚未启用 2FA 的账号使用“设置 2FA”；已启用的账号使用独立的“重置 2FA”。已有 2FA 时，首次设置按钮保持禁用。
- 单账号入口位于账号行右侧“重置 2FA”按钮。勾选多个账号后，可使用“批量重置 2FA”；确认窗口显示本次可执行数量和跳过数量，服务端重新检查资格并去重。
- 重置先移除旧因子，再创建并启用新密钥。旧验证器中的验证码会失效；中途失败可能暂时没有有效 2FA。
- 确认卡片提供“退出所有设备”“重登授权”和“授权后自动上传 Sub2API”开关。三个偏好保存在当前浏览器，取消、关闭和刷新后保留；初始均关闭。“清除本机网页配置”同时清除此偏好。首次设置不提供退出选项。
- 自动上传依赖重登授权和已保存的 Sub2API 配置。关闭重登会关闭自动上传；未配置时可从卡片进入 Sub2API 设置。卡片实时展示选定流程，提交后的执行状态持续显示在账号行。
- 只有点击确认才提交操作。退出请求在新 2FA 验证成功且密钥安全保存后执行，包括当前网页登录；只有可靠确认请求尚未发送的临时网络错误可重试。退出失败或已发送后结果未知不会重新执行重置或自动补发退出。

执行顺序为：更新并安全保存 2FA → 可选退出所有设备 → 可选全新登录并授权 → 可选同步 Sub2API。退出结果必须确认为成功才继续重登；任一步失败、取消或结果未确认均停止后续步骤。服务端执行流程，关闭网页不会触发重复操作。重置成功后，“导出原始信息”读取当前保存的新密钥；密钥修改中或恢复未完成时拒绝导出。

退出所有设备开始时，旧 OAuth 授权文件即停用；仅退出而未重登、退出结果未知或流程中断时，不会把旧文件当作有效授权上传。后续独立重登取得新授权后恢复上传资格。

程序没有重置次数限制。上一轮新密钥已经验证并安全保存、没有凭据恢复风险且流程已结束时，即使退出设备或后续重登失败，也可再次手动确认重置。缺少旧授权或登录检查点时，新的重置会重新登录。退出成功但没有选择重登的账号同样适用；按钮资格由单账号及批量操作共用。

每个独立 HTTP 请求都有自己的重试预算，默认首次尝试加最多 3 次重试，并非仅流程中的第一个请求。登录预检、状态查询、动态认证脚本、邮箱、短信、Sub2API 查询遇到临时超时、断连、网络不可达或握手中断时可重试。HTTP 拒绝、明确业务错误、证书验证失败、永久 DNS/协议错误不重试，用户取消或父任务总期限到达时停止。日志只追加次数及安全原因，不覆盖当前操作或手动输入提示。

提交验证码、OAuth 兑换、移除/创建/激活因子和退出设备等写请求，以及带一次性授权码或 token 的回调导航，只在传输层可靠确认尚未取得可发送 HTTP 的连接时重试。已发送后超时、响应丢失或结果未知不重放。购买短信号码、修改号码状态、Sub2API 新建/更新账号同样遵守此规则。

尚未移除旧因子、密钥未变化且没有恢复风险的任务，网络失败后可再次手动重置。移除请求所有尝试都被确认尚未发送时，程序先保存安全的初始阶段记录，再恢复原安全凭据并读回校验，最后解除本次隔离；同邮箱其他记录有独立恢复风险时仍阻止解除。服务重启后资格保持，整个流程不会自动重新开始。单次请求超时不会误标为整个任务中断。

仍在运行或排队、密钥尚未确认、恢复记录未处理时继续阻止重置。允许手动新操作不会自动重放上一轮流程，也不会恢复旧授权的下载或上传资格；私有恢复记录和安全凭据状态仍在入队及执行前核验。

## 接口和实现

单账号使用 `POST /api/jobs/{id}/setup-2fa`，批量使用 `POST /api/jobs/setup-2fa-batch` 并传入 `ids`。两者接受严格布尔字段 `resetTotp`、`logoutAllDevicesAfterTotp`、`reloginAfterTotp` 和 `uploadAfterTotp`，缺省均为 `false`；字符串、数字、数组、对象和 `null` 均被拒绝。只有 `resetTotp: true` 时才允许退出；只有 `reloginAfterTotp: true` 时才允许上传。开启上传时传入 `sub2apiConfig`，格式与已保存的网页 Sub2API 设置一致，入队前验证。

公开任务和跨页选择数据分别提供设置/重置资格、禁用原因、重置状态、恢复状态及退出结果，不包含密钥。操作由 Go 控制台、任务管理器和协议流程执行；网页由 Go esbuild 构建，认证沿用 Go HTTP/TLS 和 Go Sobek worker，不依赖 Node、Python 或浏览器自动化。

后续流程公开 `totpWorkflowStatus`、`totpWorkflowStep`、`totpReloginStatus`、`totpUploadStatus` 及脱敏错误。流程意图和状态保存在任务元数据；Sub2API 管理密钥只进入任务私有输入，不写入任务元数据、日志或公开接口。重启时未完成的流程标为中断，不自动重放。

## Sub2API 授权同步

手动上传和 2FA 后自动上传共用 Go 上传客户端。客户端完整分页查询 OpenAI OAuth 账号，按规范化邮箱匹配，并读取匹配账号详情。已有账号只更新合并后的 OAuth 授权字段，保留远端模型映射、名称、号池、代理、优先级、并发、指纹及其他设置；不存在才使用当前上传配置创建账号。

查找失败、分页不完整、身份不一致或同邮箱存在多个候选时停止上传，不尝试新建。同次上传去重，本进程到同一 Sub2API 后端的上传串行执行。跨程序同时创建仍取决于远端唯一约束，接口不提供跨客户端事务。

## 保存与中断

发送移除请求前，程序先保存私有阶段记录、持久安全凭据中的待恢复标记和任务元数据，并核对凭据读回结果。只有内存存储或持久保存不可用时停止；不会把内存保存当作安全持久化成功。

协议从当前账号查询并核实唯一有效的普通 TOTP 因子，移除后再次查询确认，再创建、激活和核实新因子。新密钥必须安全保存并读回一致，任务才标记为完整成功。发送修改请求前清除旧登录检查点，防止随后继续旧认证会话。

修改因子请求的断连、超时，以及激活后核实失败或保存失败，可能留下未知结果。程序保留私有恢复材料，停用旧密钥的自动使用，并阻止同账号的重新登录、再次重置、自动修复和资料导出。服务重启只处理可验证的本地恢复信息，不自动重放移除、激活或退出请求。需要人工核实时，应保留恢复材料，核实账号当前有效因子及密钥后再处理恢复，不能把“请求结果未知”视为操作未发生。
