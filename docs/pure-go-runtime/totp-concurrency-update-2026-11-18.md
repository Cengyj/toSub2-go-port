# 同账号并发 2FA 实测后的代码更新

2026-11-18。此文件记录实测结束后的修复，不改写旧实验结论。旧实验使用同一账号的独立 A/B 登录会话；本次代码验证使用合成响应和临时凭据，不再修改测试账号的 2FA。

## 实测依据与本次处理

| 已观察事实 | 原程序问题 | 本次处理 |
| --- | --- | --- |
| 同一账号可同时拥有不同且有效的 TOTP 密钥；验证必须匹配各自 factor ID | 登录只选返回列表第一个因子，第二把有效密钥被误配后得到 incorrect_code | 密钥与 factor ID 一起加密保存；登录使用已保存且在本次服务端列表中的 ID |
| 两次重叠删除同一 F0 均获 200，随后双方都成功登记、激活 | 移除后设置分支只凭激活回执提交成功，没有复查当前显示因子 | 两条重置分支都在激活后进行有界只读复查，匹配才提交已确认凭据 |
| mfa_info 可能仅显示多个有效因子中的一个 | 日志把单个显示因子当成“唯一有效验证器” | 明确记录激活回执、当前查询匹配、本地保存三个检查点；不声称其他密钥失效 |
| 延迟删除已过期 F0 返回 400/Invalid request，当前新因子未受影响 | 不能把重叠删除的双成功推断为所有重复删除幂等 | 保持明确拒绝即停止；回归保证不改删新 ID、不自行补设 |
| logout_all 200/null 后，session 可继续 200，但受保护接口返回 401/token_revoked | 成功标签容易被理解为逐个验证所有会话已失效 | 日志描述为服务器接受退出请求；保留 token_revoked 业务代码并说明其含义 |

证据报告：[两个密钥的独立验证](totp-dual-key-login-verification-2026-11-18.md)、[同时删除及后续设置](totp-simultaneous-removal-2026-11-18.md)、[退出后的只读探测](totp-concurrency-logout-evidence-2026-11-18.md)。报告中的原程序行为属于修改前版本。

## 持久化和恢复

受保护凭据增加 `totpFactorId`、`pendingTotpFactorId`。待激活材料仍先保存并完整读回，再发送激活；确认后提升为有效密钥及对应绑定。非 2FA 凭据更新保留同一密钥的绑定，导入不同密钥时清除旧绑定。公开任务元数据和日志不输出真实密钥或因子 ID。

自动验证码验证明确成功后才保存其密钥与因子绑定；手工输入验证码不能证明某把已保存密钥有效。旧加密凭据没有 ID 时继续可读：本次仅返回一个可选因子，可在验证成功后补齐；返回多个则明确报 `MFA_FACTOR_AMBIGUOUS`，不会猜第一个或轮流试码。已绑定因子不在登录响应中时报 `MFA_FACTOR_BINDING_MISSING`，不会把该密钥提交给另一因子。

新重置证据采用 `activation_evidence_schema=3`，记录实际当前因子核对时间并绑定到本次操作、账号和登记材料。激活回执成功但复查不一致时，保留待处理密钥及回执，结果待核实并停止后续修改、退出和上传。该状态不等于密钥无效，也不能仅靠“完成本地保存”绕过复查。

历史 schema=2 的有效业务回执继续按原有语义支持纯本地完成，不补造远端查询。冲突的非空因子绑定阻止覆盖。恢复过程中核对已有材料，避免把旧密钥的因子 ID 转移给另一把密钥。普通设置激活后崩溃时，匹配的待保存材料与登记记录可恢复因子绑定；旧设置文件缺少对应待保存材料时，不能覆盖另一把现有有效密钥。

## 行为范围

- 产品账号互斥继续阻止同账号的本地并发操作；它不能阻止其他设备或另一独立产品实例修改账号。
- `mfa_info` 匹配仅说明该次查询的结果；其他会话仍可能随后更改当前因子。即使两次操作各自复查匹配，也不能宣称账号只剩一把密钥。
- “初始未找到因子，首次登记明确提示已存在”仍仅使用原有严格解析和一次回退。实测没有获得该冲突响应，不增加对普通 409、未知文案的推测匹配。
- 结果未知的修改仍不重发；只读查询使用现有有限预算，遇到明确身份错误或第三方因子即停止，不引入互删互设循环。
- 激活后新增复查覆盖 `ResetTOTP` 的初始登记与移除后登记两条分支。历史独立 CLI `--setup-totp` 保持其激活确认规则；它也使用新的登录与凭据绑定。
- 退出日志的成功表示接口接受请求，不是新的在线失效测量。本轮没有再次退出测试账号。
