# 2FA 状态同步、先设置回退与日志改进（2026-11-17）

## 改变的行为

网页登录和账号身份校验完成后单独输出“账号登录成功”；后续读取、判断、移除、设置、激活和验证分别显示阶段。任务仍在运行时，登录成功和旧验证器已移除显示为已完成的步骤。历史特定英文错误在界面中解释为登录已完成但未识别到可移除验证器，原始日志仍可查看。

初始状态查询最多进行 4 次，间隔 0.5、1、2 秒，并复用当前登录会话。HTTP 暂时失败与可理解但缺失/未启用的状态共用该预算。成功登录不会因为状态暂未同步而重复登录。

- 明确存在唯一有效的普通 TOTP：按原流程移除，再设置并激活新的 2FA。
- 未启用或可理解但缺少必要信息：先建立持久操作记录和凭据隔离，再尝试一次设置。
- 初次设置成功：保存新密钥后激活，再只读确认唯一有效验证器是本次新验证器，才报告重置完成。
- 初次设置明确被“已存在 2FA”拒绝：完整拒绝回执可靠保存后，在原会话最多读取 4 次；只有取得唯一有效普通 TOTP 才移除一次，然后进行一次新的设置和激活。
- 多个验证器、恢复验证器、业务拒绝、畸形状态、未知设置结果、网络中断或缺失目标 ID：不据此猜测删除对象，也不重复发送未知结果的修改请求。

## 可追溯的操作证据

初次设置使用独立的 `initial_enroll_attempt_id`、`initial_enroll_dispatch`、`initial_enroll_receipt`。回退后的正常设置使用原 `enroll_*` 字段，不覆盖第一次响应。`reset_totp_strategy=enroll_first` 明确允许尚无旧验证器 ID 的操作身份，须有完整当前版本证据；旧格式不能带新增字段绕过校验。初次设置的发送时间、编号、回执和结果均不能被普通重试覆盖。

新密钥只有在安全保存并读回后才能激活。遇到未知结果仍保留回执/材料，重启后不自动重复修改账号。直接设置路径还需验证新验证器唯一性，防止“追加一个验证器”被误报为“替换完成”。
